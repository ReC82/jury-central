5. Dossiers d'examen résolus

Format type de l'épreuve pratique écrite : un contexte, des documents (captures, relevés, sorties de commandes), des questions numérotées. La réponse attendue est rédigée, ordonnée, justifiée ; chaque action est accompagnée de sa précaution et de son contrôle.

Dossier 1 — Cabinet comptable Dumont : Windows 11 ne démarre plus après une coupure de courant

Contexte : PC de bureau, Windows 11 Professionnel, SSD NVMe 512 Go, BitLocker non activé. Coupure de courant pendant l'installation des mises à jour hier soir. Ce matin, l'écran ci-dessous s'affiche. La comptable a besoin de ses dossiers (dossier C:\Compta, non sauvegardé depuis 15 jours).

Votre PC/appareil doit être réparé
Le fichier de données de configuration de démarrage ne contient pas
d'informations valides pour un système d'exploitation.
Fichier : \EFI\Microsoft\Boot\BCD
Code d'erreur : 0xc000000f

Document 2 (WinRE, invite de commandes) :

DISKPART> list vol
  Volume 0     E   CCCOMA_X64F  UDF    DVD-ROM     5 Go
  Volume 1     D                NTFS   Partition   475 G    Sain
  Volume 2                      NTFS   Partition   750 M    Sain   Masqué
  Volume 3                      FAT32  Partition   100 M    Sain   Masqué
  1. À quel stade du démarrage se situe la panne ? Justifie.
  2. Quelle est ta toute première préoccupation, et comment y réponds-tu ?
  3. Décris la procédure de réparation, du moins invasif au plus invasif, avec les commandes exactes.
  4. Pourquoi n'utilises-tu pas bootrec /fixmbr ?
  5. Comment valides-tu l'intervention et que notes-tu dans le rapport ?

Réponse rédigée attendue

1. Le message est affiché par Windows Boot Manager : le firmware a trouvé le disque et lancé le chargeur de l'ESP, mais le magasin BCD est invalide. La panne se situe donc au stade du chargeur, après le firmware et avant le noyau. Le disque est lu : ce n'est pas un problème de détection.

2. Les données de C:\Compta, sans sauvegarde récente. Avant toute commande qui modifie le démarrage, je copie ce dossier : soit depuis WinRE (notepad → Fichier → Ouvrir sert d'explorateur pour copier vers une clé USB), soit depuis une clé live Linux en lecture. Je vérifie la copie (ouverture de fichiers témoins).

3. a) Clé d'installation Windows 11 → Réparer l'ordinateur → Dépannage → Options avancées → Outil de redémarrage système. b) Si échec : invite de commandes, lecture bcdedit /enum all. c) Identification des volumes (document 2) : Windows sur D: (475 Go NTFS ; je confirme par dir D:\Windows), ESP = volume 3 (FAT32, 100 Mo, masqué). d) diskpart → select vol 3 → assign letter=S → exit. e) bcdboot D:\Windows /s S: /f UEFI → « Boot files successfully created ». f) Redémarrage sans la clé. g) Si Windows démarre mais reste instable (coupure pendant MAJ) : DISM /Online /Cleanup-Image /RestoreHealth puis sfc /scannow, et chkdsk C: en lecture. Je n'utilise ni clean ni format dans diskpart, et je ne réinstalle pas.

4. Le PC démarre en UEFI (chemin \EFI\Microsoft\Boot\BCD, ESP FAT32) : le code d'amorçage du MBR n'intervient pas dans ce démarrage. bootrec /fixmbr est un outil du démarrage hérité ; il ne reconstruirait pas le BCD. L'outil adapté est bcdboot.

5. Validation : deux démarrages complets sans clé ; bcdedit /enum montre device partition=C: et winload.efi ; Windows Update terminé ; sfc sans violation ; la comptable ouvre ses dossiers. Rapport : symptôme et code exacts, cause (BCD endommagé par la coupure), copie de sauvegarde réalisée, commandes exécutées, résultats, contrôles ; recommandation d'un onduleur et d'une sauvegarde automatique quotidienne.

Perd des points : réinstaller Windows ; confondre avec « No bootable device » ; lancer bcdboot C:\Windows sans vérifier que C: est bien Windows dans WinRE ; oublier la sauvegarde des données.

Dossier 2 — Bureau d'architectes : installation propre de Windows 11 sur un SSD neuf, puis pilotes manquants

Contexte : un poste de 2020 (Intel Core i7 de 10e génération, 16 Go) reçoit un SSD neuf de 1 To. Licence Windows 11 Professionnel. Le client veut une installation propre ; les données sont sur le NAS. Relevé msinfo32 sous l'ancien Windows 10 :

Mode BIOS                       Hérité
État du démarrage sécurisé      Non pris en charge
Processeur                      Intel(R) Core(TM) i7-10700
Mémoire physique installée      16,0 Go

tpm.msc : « Impossible de trouver le module de plateforme sécurisée compatible ». Après installation, Gestionnaire de périphériques :

Autres périphériques
  ! Contrôleur Ethernet       ID : PCI\VEN_8086&DEV_0D55
  ! Périphérique PCI          ID : PCI\VEN_8086&DEV_06A3
  ! Contrôleur audio multimédia
  1. Le poste peut-il recevoir Windows 11 ? Que faut-il régler, et dans quel ordre ?
  2. Rédige la procédure d'installation (préparation → validation).
  3. Comment traites-tu les pilotes manquants, alors que le réseau ne fonctionne pas ?
  4. Quels comptes crées-tu pour les trois architectes, et pourquoi ?

Réponse rédigée attendue

1. Oui : un i7 de 10e génération et 16 Go répondent aux prérequis ; seuls des réglages bloquent : mode hérité (Secure Boot impossible sans UEFI) et TPM désactivé. Le SSD étant neuf et vide, pas de conversion à faire : 1) setup firmware : activer Intel PTT (TPM 2.0) ; 2) Boot Mode UEFI, CSM désactivé ; 3) Secure Boot activé (clés par défaut) ; 4) noter les réglages d'origine dans le rapport. Les données étant sur le NAS, l'ancien disque est conservé intact (débranché pendant l'installation pour éviter toute erreur de cible).

2. Préparation : accord écrit, inventaire, licence Pro vérifiée, ISO officielle (empreinte SHA-256 vérifiée), clé créée avec l'outil de Microsoft, pilotes du fabricant (réseau, chipset, audio) téléchargés sur une seconde clé. Installation : démarrage sur « UEFI: clé » (F12) ; langue ; édition Professionnel (celle de la licence) ; « Personnalisé » ; disque cible identifié par sa taille (931 Go, espace non alloué) ; Suivant (l'installateur crée ESP, MSR, Windows, récupération en GPT). Configuration : compte administrateur du poste, réseau, mises à jour. Validation : msinfo32 → UEFI + démarrage sécurisé activé ; Gestionnaire de périphériques sans triangle ; activation ; Windows Update à jour ; tests (réseau, son, impression, NAS) ; point de restauration ; rapport.

3. VEN_8086 = Intel. DEV_0D55 est un contrôleur Ethernet Intel, DEV_06A3 un contrôleur de bus SM (chipset). Sur un autre PC, je télécharge depuis la page support du modèle exact (ou Intel) le pilote réseau et le pack chipset ; je les installe depuis la clé (chipset d'abord, puis réseau). Le réseau fonctionnant, Windows Update → Options avancées → Mises à jour facultatives fournit le pilote audio, sinon celui du fabricant. Contrôle : plus aucun périphérique dans « Autres périphériques », son et réseau testés.

4. Un compte standard par architecte (traçabilité, profils séparés) et un compte administrateur distinct réservé à la maintenance, au mot de passe connu du seul responsable. Principe du moindre privilège : un logiciel malveillant lancé depuis une session standard ne peut pas modifier le système ; les installations se font par élévation UAC. Pas de compte partagé.

Perd des points : conclure « incompatible » sur la ligne « Non pris en charge » ; laisser l'ancien disque branché et choisir « le premier disque » ; installer l'édition Famille ; donner les droits administrateur aux trois utilisateurs.

Dossier 3 — Association « Le Relais » : Ubuntu en mode d'urgence après remplacement du disque de données, puis impossible d'ajouter une imprimante

Contexte : poste Ubuntu ; le disque de données (monté sur /data) a été remplacé hier par un bénévole qui a recopié les fichiers. Ce matin :

[ TIME ] Timed out waiting for device /dev/disk/by-uuid/0d4e5f61-aaaa-4b2c-9d8e-112233445566.
[DEPEND] Dependency failed for /data.
[DEPEND] Dependency failed for Local File Systems.
You are in emergency mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, ...
Cannot open access to console, the root account is locked.

lsblk -f (depuis une clé live) :

sda1      ext4   data  9b1c7e2d-5a40-4c1e-8f7e-2d0c6b1e44aa
nvme0n1p1 vfat         4C2E-91AB
nvme0n1p2 ext4         3f2a8d10-77c1-4f0b-9a55-6e3d2c1b0f12

Après réparation, la bénévole Sarah (compte standard) veut ajouter une imprimante dans Paramètres → Imprimantes ; le bouton Ajouter demande un mot de passe d'administrateur. id sarah : groups=1001(sarah).

  1. Explique le message et la cause la plus probable.
  2. Comment accèdes-tu au système, alors que le compte root est verrouillé ?
  3. Rédige la correction avec ses précautions et son test avant redémarrage.
  4. Comment permets-tu à Sarah d'ajouter des imprimantes sans en faire une administratrice ?

Réponse rédigée attendue

1. systemd attend le périphérique d'UUID 0d4e… listé dans /etc/fstab pour monter /data ; il n'existe pas, le montage échoue, et comme /data fait partie des « Local File Systems », le démarrage s'arrête en mode d'urgence. lsblk -f montre que le nouveau disque a l'UUID 9b1c… : un UUID change à chaque création de système de fichiers. Cause : ligne fstab qui désigne l'ancien disque.

2. Ubuntu verrouille root : le mode d'urgence ne peut ouvrir de console. Je démarre par GRUB → Advanced options → (recovery mode) → root, ou sur la clé live (montage de la racine nvme0n1p2).

3. mount -o remount,rw / (la racine est en lecture seule en recovery) ; cp /etc/fstab /etc/fstab.bak ; dans /etc/fstab, je remplace l'UUID 0d4e… par 9b1c7e2d-5a40-4c1e-8f7e-2d0c6b1e44aa et j'ajoute nofail (disque de données non indispensable au démarrage) : UUID=9b1c7e2d-… /data ext4 defaults,nofail 0 2. Test avant redémarrage : findmnt --verify (aucune erreur), systemctl daemon-reload, mount -a (silencieux), findmnt /data (monté). Puis redémarrage : démarrage normal, systemctl --failed vide, fichiers de /data présents.

4. Sous Ubuntu, la gestion des imprimantes (CUPS) est autorisée aux membres du groupe lpadmin. Avec l'accord du responsable : sudo usermod -aG lpadmin sarah (le -a conserve ses autres groupes), puis déconnexion/reconnexion. Contrôle : id sarah montre lpadmin, elle ajoute l'imprimante et imprime une page de test ; elle n'est pas dans sudo.

Perd des points : reformater ou réinstaller ; utiliser /dev/sda1 dans fstab ; redémarrer sans test ; ajouter Sarah au groupe sudo.

Dossier 4 — Agence immobilière : écran bleu après mise à jour d'un pilote, choix de la restauration

Contexte : portable Windows 11 ; depuis le 21/10, écran bleu au bout de quelques minutes de visioconférence. Journal Système :

21/10 10:14  Kernel-Power 41  (Critique)
21/10 10:14  BugCheck 1001 : La vérification d'erreur était : 0x000000d1 ...
             Un vidage a été enregistré dans : C:\Windows\Minidump\102126-...dmp
21/10 09:02  Kernel-PnP 400 : Périphérique PCI\VEN_8086&DEV_2725 configuré
             Nom du pilote : oem42.inf  Version : 23.60.0.3  Date : 10/10/2026

Écran relevé : DRIVER_IRQL_NOT_LESS_OR_EQUAL, « Ce qui a échoué : Netwtw14.sys ». Points de restauration : 15/10 (Windows Update), 21/10 08:59 (« Installed Intel Wi-Fi driver »), 24/10 (Windows Update). Le client n'a aucune sauvegarde de ses documents.

  1. Interprète les documents : observation, hypothèse, ce qui n'est pas une cause.
  2. Quel est le premier test discriminant, et sa correction ?
  3. Si le test échoue, quel point de restauration choisis-tu et que vas-tu perdre ?
  4. Quelle précaution impose l'absence de sauvegarde ?

Réponse rédigée attendue

1. Observation : écrans bleus DRIVER_IRQL_NOT_LESS_OR_EQUAL (0xD1) citant Netwtw14.sys, le pilote Wi-Fi Intel ; le journal montre l'installation d'une nouvelle version du pilote de la carte VEN_8086&DEV_2725 (Wi-Fi Intel AX210) le 21/10 à 09:02, une heure avant le premier écran bleu ; la visioconférence sollicite justement le Wi-Fi. Hypothèse principale : pilote Wi-Fi récent défectueux ; hypothèse secondaire : mémoire. Le Kernel-Power 41 n'est pas une cause : il constate seulement que le PC a redémarré sans arrêt propre.

2. Test : Gestionnaire de périphériques → Cartes réseau → Intel Wi-Fi 6 AX210 → Propriétés → Pilote → Restaurer le pilote (version précédente) ; redémarrer ; reproduire une visioconférence d'au moins une heure. Aucun écran bleu → cause confirmée. Puis suspendre la mise à jour de ce pilote et surveiller le journal (aucun nouvel événement 1001) pendant une semaine.

3. Le point du 21/10 à 08:59 : c'est le dernier point antérieur à l'installation du pilote (09:02) et donc à la panne ; le point du 15/10 ferait perdre inutilement six jours de changements, celui du 24/10 contient déjà le pilote fautif. Avant de lancer, « Rechercher les programmes concernés » liste ce qui sera retiré. La restauration retirera les pilotes, programmes et mises à jour installés après le point (dont le pilote Wi-Fi et la mise à jour du 24/10, qui se réinstallera) ; elle ne touche pas aux documents.

4. Une restauration n'est pas une sauvegarde : avant toute intervention, je copie les documents du client sur un support externe et je vérifie la copie. Je recommande ensuite une sauvegarde automatique (Historique des fichiers ou cloud).

Perd des points : « carte Wi-Fi HS » ; prendre Kernel-Power 41 pour la cause ; choisir le point le plus ancien sans raison ; présenter la restauration comme sans risque pour les données sans avoir sauvegardé.
