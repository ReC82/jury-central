3.D Procédures — Lenteurs, logiciels, services, logiciels malveillants

P4.1 — Le PC Windows est lent (démarrage, ouverture des programmes, gel temporaire)

Fréquence : très fréquent · Gravité : faible à moyenne (peut révéler un disque qui meurt)

1. Symptômes observables

  • Démarrage de plusieurs minutes, curseur « occupé », programmes lents, ventilateur bruyant, gels de quelques secondes, voyant du disque allumé en permanence.

2. Causes possibles (classées)

  1. Trop de programmes au démarrage / en arrière-plan — configuration/applications.
  2. Mises à jour ou indexation en cours (temporaire) — OS.
  3. Disque presque plein (< 10 % libre) — stockage.
  4. Disque dur mécanique saturé (100 %) ou qui faiblit (secteurs réalloués) — matériel.
  5. RAM insuffisante (mémoire > 90 %, fichier d'échange) — matériel/usage.
  6. Logiciel malveillant, extensions de navigateur — sécurité.
  7. Surchauffe → baisse de fréquence (throttling) — matériel.
  8. Mode d'alimentation « Économie » sur portable — configuration.

3. Questions initiales et sécurité

  • Depuis quand ? Progressif (accumulation) ou brutal (changement, panne) ? Tous les programmes ou un seul ? Tous les comptes ? Sur secteur ou batterie ?
  • Si le disque fait des bruits ou si les journaux signalent disk 7/153 : sauvegarde AVANT toute optimisation.

4. Diagnostic pas à pas

  1. Gestionnaire des tâches (Ctrl+Maj+Échap) → Processus, trié par Processeur, Mémoire, Disque ; onglet Performance (type de disque HDD/SSD, « Temps d'activité » du disque, mémoire utilisée/totale). Moniteur de ressources (resmon) pour le détail disque.

    SI Disque à 100 % durablement sur un HDD → étape 4.

    SINON SI Mémoire > 90 % → identifier le processus gourmand ; si l'usage normal dépasse la RAM → ajout de RAM (Fiche 1). SINON SI Processeur élevé par un processus inconnu → P4.6.

  2. Onglet Démarrage / « Applications de démarrage » (Windows 11 ; aussi Paramètres → Applications → Démarrage) : colonne « Impact du démarrage ». Désactiver ce qui n'est pas nécessaire (avec l'utilisateur), jamais l'antivirus ni les pilotes audio/touchpad.
  3. Paramètres → Système → Stockage : espace libre de C:.

    SI < 10 % libre → P5.5.

    SINON → étape 4.

  4. Santé du disque : journal Système (sources disk, Ntfs, stornvme : ID 7, 51, 153, 129), SMART (→ Fiche 1), chkdsk C: (lecture).

    SI erreurs → sauvegarde, remplacement par un SSD (Fiche 1).

    SINON → étape 5.

  5. Températures/fréquence (Gestionnaire des tâches → Performance → Processeur : « Vitesse » très inférieure à la « Vitesse de base » sous charge) → Fiche 1 · Surchauffe ; mode d'alimentation (Paramètres → Système → Alimentation et batterie → Mode d'alimentation).
  6. Démarrage minimal pour isoler : msconfig → Services → « Masquer tous les services Microsoft » → Désactiver tout ; Démarrage → Gestionnaire des tâches → tout désactiver ; redémarrer.

    SI rapide → un service/programme tiers : réactiver par moitiés jusqu'à trouver le coupable.

    SINON → système/matériel : DISM+SFC (P6.3), malveillant (P4.6).

Attention Après un démarrage sélectif msconfig, revenir à « Démarrage normal » à la fin : sinon services d'impression, VPN, antivirus tiers restent désactivés. Ne jamais cocher « Rendre ces paramètres permanents » sans raison.

5. Test de confirmation

Mesure chiffrée avant/après : temps de démarrage jusqu'au bureau utilisable (chronomètre), « Dernier BIOS » (onglet Démarrage), temps d'ouverture d'un programme métier, % disque au repos. Limite : les jours de MAJ faussent la mesure.

6. Correction

Désactiver les programmes de démarrage inutiles ; désinstaller les logiciels inutiles (Paramètres → Applications → Applications installées) ; libérer de l'espace ; SSD/RAM si mesures le justifient (Fiche 1) ; nettoyage malveillant. Pas d'« optimiseur » ni de « nettoyeur de registre ». Pas de défragmentation d'un SSD (Windows fait de l'optimisation TRIM automatiquement ; la défragmentation d'un HDD : Fiche 1).

7. Validation

  • Mesures après correction comparées aux mesures initiales, notées dans le rapport ; utilisateur confirme ; aucun programme utile désactivé (impression, synchronisation, antivirus testés).

8. Réponse d'examen modèle

Réponse rédigée attendue

Mesure initiale : bureau utilisable après 4 min 10 s ; Gestionnaire des tâches : disque (HDD) à 100 %, mémoire 7,4/8 Go, 19 applications de démarrage dont 6 d'impact élevé ; 8 % d'espace libre. Hypothèses : surcharge au démarrage, disque presque plein, disque mécanique lent ou défaillant. Tests : journal Système sans erreur disk ; SMART correct (le disque n'est pas en panne). Actions (avec accord) : désactivation de 12 programmes de démarrage non nécessaires, désinstallation de 3 logiciels inutilisés, nettoyage des fichiers système (+18 Go). Mesure finale : 1 min 35 s. Recommandation : remplacer le HDD par un SSD (gain attendu majeur), devis fourni. Démarrage normal rétabli dans msconfig.

Perd des points : « réinstaller Windows » pour une lenteur ; aucune mesure avant/après ; installer un optimiseur ; défragmenter un SSD.

9. Pièges et variantes

  • Lent seulement le matin pendant 15 min : MAJ/indexation/antivirus programmé, pas une panne.
  • Lent seulement sur batterie : mode d'alimentation, pas de matériel.
  • Lent seulement sur Internet : Fiche 4 (DNS, Wi-Fi).
  • Lenteur + bruit de clic + disk 7 : disque mourant → sauvegarde immédiate, c'est prioritaire sur la lenteur.

P4.2 — Un logiciel ne démarre pas, se ferme ou affiche une erreur

Fréquence : très fréquent · Gravité : variable (logiciel métier = élevée)

1. Symptômes observables

  • « L'exécution du code ne peut pas continuer, car VCRUNTIME140.dll (ou MSVCP140.dll) est introuvable » ; « L'application n'a pas réussi à démarrer correctement (0xc000007b) » ; « Cette application ne peut pas s'exécuter sur votre PC » ; fermeture sans message ; « Accès refusé ».
  • Journal Application : Application Error, ID 1000 (nom de l'application, module en cause, code d'exception) ; .NET Runtime, ID 1026 ; Application Hang, ID 1002.
  • Linux : command not found, error while loading shared libraries: libxxx.so: cannot open shared object file, Permission denied.

2. Causes possibles (classées)

  1. Dépendance absente (redistribuable Visual C++, .NET) — installation.
  2. MAJ du logiciel/de Windows — changement.
  3. Droits insuffisants / dossier protégé / profil — compte.
  4. Fichiers de configuration/cache abîmés dans le profil — profil.
  5. Antivirus qui bloque (quarantaine) — sécurité.
  6. Incompatibilité 32/64 bits, ARM, version de Windows — compatibilité.

3. Questions initiales et sécurité

  • Message exact ? Depuis quand ? Un utilisateur ou tous ? Un PC ou tous ? Données du logiciel (base, fichiers) sauvegardées avant réparation ?

4. Diagnostic pas à pas

  1. Observateur d'événements → Application → ID 1000/1026 à l'heure de l'échec : « Nom du module défaillant ».

    SI module = DLL tierce du logiciel → réparer/réinstaller le logiciel.

    SINON SI module = ntdll.dll/KERNELBASE.dll → peu discriminant : étapes suivantes.

  2. DLL introuvable (VCRUNTIME140.dll, MSVCP140.dll) → installer le « Microsoft Visual C++ Redistributable » officiel x64 et x86 (site Microsoft). Jamais une DLL isolée téléchargée sur un site tiers.
  3. Tester avec un autre compte (ou nouveau compte local de test).

    SI fonctionne avec l'autre compte → profil/droits : renommer le dossier de configuration du logiciel dans %APPDATA% (après copie), vérifier les droits sur le dossier de données.

    SINON → étape 4.

  4. Exécuter en tant qu'administrateur (test seulement).

    SI fonctionne en admin → le logiciel écrit dans un dossier protégé (C:\Program Files) : donner le droit Modifier sur SON dossier de données au groupe Utilisateurs, ou mettre à jour le logiciel. Ne pas rendre l'utilisateur admin.

    SINON → étape 5.

  5. Sécurité Windows → Protection contre les virus et menaces → Historique de protection : fichier mis en quarantaine ?

    SI oui et logiciel légitime vérifié (éditeur, signature) → restaurer, exclusion ciblée, signaler à l'éditeur.

    SINON → Paramètres → Applications → Applications installées → … → Modifier/Réparer ; sinon désinstaller/réinstaller (données sauvegardées) ; vieux logiciel : Propriétés → Compatibilité.

5. Test de confirmation

Le logiciel s'ouvre et l'action métier (ouvrir un dossier client, imprimer une facture) fonctionne, avec le compte de l'utilisateur, sans élévation. Limite : un succès en admin ne confirme pas la correction.

6. Correction

Dépendance installée ; réparation/réinstallation ; profil de config réinitialisé ; droits ciblés ; désinstallation de la MAJ fautive (P3.5) ou restauration (P6.2).

7. Validation

  • Fonction métier testée par l'utilisateur ; journal Application sans nouvel ID 1000 ; autres logiciels toujours fonctionnels.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le logiciel de facturation ne démarre plus depuis la mise à jour d'hier, pour tous les utilisateurs du poste. Le journal Application montre un événement 1000 avec le module MSVCP140.dll. Hypothèse : redistribuable Visual C++ manquant ou abîmé. Je télécharge sur le site de Microsoft le redistribuable Visual C++ x86 et x64, je le répare/installe, puis je relance : le logiciel démarre, une facture test est imprimée. Validation avec l'utilisateur, aucun nouvel événement 1000.

Perd des points : copier une DLL d'un site inconnu ; donner les droits administrateur à l'utilisateur ; réinstaller sans sauvegarder la base du logiciel.

9. Pièges et variantes

  • Linux command not found : paquet absent, faute de frappe, dossier hors PATH ; Ubuntu propose souvent le paquet (sudo apt install net-tools) — préférer la commande moderne (ip a au lieu de ifconfig).
  • Linux Permission denied sur un script : droit d'exécution (chmod u+x script.sh) ou partition montée noexec.
  • Logiciel réseau qui « ne démarre pas » car le serveur/partage est inaccessible → Fiche 4 · Partage.

P4.3 — Un service Windows ne démarre pas ou s'arrête (ex. Spouleur d'impression)

Fréquence : fréquent · Gravité : moyenne à élevée (impression, sauvegarde, logiciel métier)

1. Symptômes observables

  • services.msc : statut vide (arrêté) ; à la tentative de démarrage : « Erreur 1053 : le service n'a pas répondu assez vite à la demande de lancement ou de contrôle », « Erreur 1068 : le service ou le groupe de dépendance n'a pas pu démarrer », « Erreur 1069 : le service n'a pas démarré en raison d'un échec d'ouverture de session », « Erreur 5 : Accès refusé ».
  • Journal Système, source Service Control Manager : 7000 (n'a pas pu démarrer), 7001 (dépendance), 7009 (délai), 7031/7034 (arrêt inattendu), 7038 (ouverture de session).

2. Causes possibles (classées)

  1. Type de démarrage Désactivé/Manuel — configuration.
  2. Dépendance arrêtée — configuration.
  3. Mot de passe du compte de service changé/expiré — compte.
  4. Fichier/pilote corrompu (ex. pilote d'imprimante qui fait planter le spouleur) — logiciel.
  5. Logiciel malveillant qui désactive (antivirus, Windows Update) — sécurité.

3. Questions initiales et sécurité

  • Droits administrateur nécessaires ; noter l'état initial (type, compte) avant de modifier.

4. Diagnostic pas à pas

  1. Propriétés du service → Général (type de démarrage, état) → Démarrer, lire le message exact.

    SI 1068 → onglet Dépendances : démarrer d'abord le service dont il dépend (et comprendre pourquoi il était arrêté).

    SINON SI 1069 → onglet Connexion : ressaisir le mot de passe du compte (ou « Compte système local » si c'est la configuration d'origine). SINON 1053 / 7031 → étape 2.

  2. Journal Système et Application à l'heure de l'arrêt : fichier ou module cité.

    SI spouleur qui s'arrête dès qu'on imprime → pilote d'imprimante abîmé : arrêter le spouleur, vider C:\Windows\System32\spool\PRINTERS (travaux bloqués), supprimer/réinstaller le pilote (Gestion de l'impression printmanagement.msc, éditions Pro).

    SINON → réparer/réinstaller le logiciel propriétaire du service ; DISM/SFC pour un service Windows.

C:\> sc query spooler
C:\> sc qc spooler
C:\> net stop spooler
C:\> del /q C:\Windows\System32\spool\PRINTERS\*
C:\> net start spooler
SERVICE_NAME: spooler
        TYPE               : 110  WIN32_OWN_PROCESS (interactive)
        STATE              : 1  STOPPED
        WIN32_EXIT_CODE    : 0  (0x0)
...
        START_TYPE         : 2   AUTO_START
        DEPENDENCIES       : RPCSS
                           : http

Attention Vider le dossier spool\PRINTERS supprime les travaux d'impression en attente (à prévenir). Ne pas désactiver un service Windows « pour voir » sans noter son état initial.

5. Test de confirmation

Service « En cours d'exécution » après un redémarrage du PC (preuve que le type de démarrage est bon) et fonction testée (page imprimée). Limite : un service qui démarre puis s'arrête 1 min après (7031) demande d'attendre.

6. Correction

Type de démarrage correct (Automatique), dépendance réparée, mot de passe de service, pilote fautif retiré. Onglet Récupération : « Redémarrer le service » après 1re défaillance (contournement, pas une correction).

7. Validation

  • sc query → RUNNING après redémarrage ; pas de 7031 dans les 24 h ; utilisateur imprime.

8. Réponse d'examen modèle

Réponse rédigée attendue

Aucune impression possible ; services.msc montre le Spouleur d'impression arrêté ; le journal Système contient des événements 7031 (arrêt inattendu) à chaque tentative d'impression depuis l'installation de la nouvelle imprimante. Hypothèse : pilote de la nouvelle imprimante qui fait planter le spouleur. Test : j'arrête le spouleur, vide les travaux bloqués, le redémarre ; une impression vers l'ancienne imprimante fonctionne, vers la nouvelle le service s'arrête : cause confirmée. Correction : suppression du pilote, installation de la version du fabricant pour ce modèle et cette version de Windows. Validation : impression réussie, service en cours d'exécution après redémarrage, plus de 7031.

9. Pièges et variantes

  • Imprimante réseau « hors ligne » avec spouleur démarré → réseau/adresse de l'imprimante : Fiche 4 · Imprimante.
  • Service Windows Update/antivirus désactivé et impossible à réactiver → suspicion de malveillant (P4.6).

P4.4 — Linux : un service est en échec (« failed »), le site ou le serveur ne répond plus

Fréquence : fréquent · Gravité : élevée (service rendu à d'autres)

1. Symptômes observables

  • Au démarrage : [FAILED] Failed to start nginx.service - A high performance web server… ; systemctl status : Active: failed (Result: exit-code).

2. Causes possibles (classées)

  1. Erreur de syntaxe après modification de la configuration — configuration.
  2. Port déjà utilisé par un autre service — conflit.
  3. Droits sur un fichier (certificat, dossier de journaux) — permissions.
  4. Disque plein — stockage.
  5. Dépendance (réseau, montage) — ordre de démarrage.

3. Questions initiales et sécurité

  • Qu'est-ce qui a été modifié ? Copie de la config avant toute modification (sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak).

4. Diagnostic pas à pas

  1. systemctl --failed puis systemctl status nginx : état, enabled/disabled, dernières lignes.
  2. journalctl -u nginx -b --no-pager | tail -n 30 : la ligne qui donne la cause.

    SI erreur de syntaxe (« unexpected "}" in /etc/nginx/sites-enabled/default:42 ») → corriger, puis sudo nginx -t (« syntax is ok », « test is successful »).

    SINON SI « bind() to 0.0.0.0:80 failed (98: Address already in use) » → sudo ss -tulpn | grep ':80' pour trouver l'occupant. SINON SI « Permission denied » → ls -l du fichier cité. SINON SI « No space left on device » → P5.6.

  3. Redémarrer et activer : sudo systemctl restart nginx ; si disabled : sudo systemctl enable --now nginx.
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; preset: enabled)
     Active: failed (Result: exit-code) since Tue 2026-10-27 09:12:04 CET; 3min ago
    Process: 1123 ExecStartPre=/usr/sbin/nginx -t -q -g daemon on; master_process on; (code=exited, status=1/FAILURE)

5. Test de confirmation

Test de configuration OK + active (running) + test fonctionnel (curl -I http://localhost → HTTP/1.1 200 OK). Limite : active ne prouve pas que le service répond au réseau.

6. Correction

Correction minimale de la cause ; tester la config avant restart (sshd -t, apache2ctl configtest, nginx -t) ; si nécessaire revenir à la .bak.

7. Validation

  • Redémarrage du serveur : service enabled et active (running) ; systemctl --failed : 0 ; test depuis un poste client.

8. Réponse d'examen modèle

Réponse rédigée attendue

systemctl status nginx indique failed ; le journal du service (journalctl -u nginx -b) signale une erreur de syntaxe ligne 42 de sites-enabled/default, modifiée hier. Je copie le fichier, corrige l'accolade manquante, vérifie avec sudo nginx -t (syntaxe correcte), redémarre le service (sudo systemctl restart nginx). Validation : active (running), curl -I http://localhost renvoie 200, site affiché depuis un poste client.

Perd des points : redémarrer le service en boucle sans lire le journal ; redémarrer le serveur entier sans diagnostic.

9. Pièges et variantes

  • inactive (dead) + disabled = service simplement non activé au démarrage, pas une panne.
  • enable ne démarre pas le service immédiatement (sauf --now) ; start ne le rend pas permanent.

P4.5 — Linux lent ou qui gèle

Fréquence : moyen · Gravité : moyenne

1. Symptômes observables

  • Interface lente, disque qui gratte, programmes tués (Out of memory: Killed process 4321 (firefox) dans dmesg).

2. Causes possibles (classées)

  1. Processus gourmand — application.
  2. RAM saturée → swap — capacité.
  3. Attente disque (wa élevé), disque plein ou qui faiblit — stockage.
  4. Surchauffe — matériel.

3. Questions initiales et sécurité

  • Depuis quand, quel usage, quel changement ?

4. Diagnostic pas à pas

  1. top (ou htop) : ligne load average (comparer au nombre de cœurs nproc), %Cpu(s) … wa, tri par %CPU (P) ou %MEM (M).

    SI un processus à ~100 % CPU → l'identifier (ps -fp PID), le fermer proprement, chercher pourquoi.

    SINON SI wa élevé → disque : df -h, sudo dmesg -T | grep -i error, SMART (Fiche 1).

  2. free -h : « available » faible et swap très utilisé → trop de programmes ou RAM insuffisante.
  3. systemd-analyze blame si c'est le démarrage qui est lent : service le plus long (ex. NetworkManager-wait-online.service).

5. Test de confirmation

Charge et temps de réponse revenus normaux après arrêt du processus/libération ; mesure avant/après (systemd-analyze).

6. Correction

kill PID (SIGTERM) avant kill -9 ; désactiver un service inutile au démarrage (sudo systemctl disable nom, après vérification) ; RAM (Fiche 1).

7. Validation

  • systemd-analyze avant/après ; top au repos ; utilisateur.

8. Réponse d'examen modèle

Réponse rédigée attendue

top : load average 7,8 sur 4 cœurs, wa à 2 %, un processus tracker-miner-fs à 95 % CPU (indexation après copie de 40 000 fichiers). free -h : mémoire suffisante. Cause : indexation ponctuelle ; je la laisse terminer ou la mets en pause, et vérifie ensuite la charge normale. Aucune modification lourde n'est justifiée.

9. Pièges et variantes

  • « Mémoire utilisée 90 % » sous Linux : le cache (buff/cache) est libéré à la demande ; regarder « available ».

P4.6 — Logiciel malveillant suspecté (publicités, navigateur détourné, fichiers chiffrés, antivirus désactivé)

Fréquence : fréquent · Gravité : élevée à critique (rançongiciel, vol d'identifiants)

1. Symptômes observables

  • Fenêtres publicitaires, page d'accueil/moteur de recherche changés, extensions inconnues, alertes « Votre PC est infecté, appelez le… » (arnaque au support), fichiers renommés (.locked, extension inconnue) + note de rançon, Sécurité Windows désactivée, processus inconnu gourmand.

2. Causes possibles (classées)

  1. Logiciel « gratuit » avec programmes associés / extension de navigateur — adware.
  2. Fausse alerte web (le PC n'est pas infecté, c'est une page) — arnaque.
  3. Cheval de Troie, voleur d'identifiants — malveillant.
  4. Rançongiciel — critique.

3. Questions initiales et sécurité

  • Isoler : débrancher le câble réseau / couper le Wi-Fi (pas d'arrêt brutal si rançongiciel en cours : avis d'escalade).
  • Fichiers partagés touchés ? Autres postes ? Mots de passe saisis ? Prévenir le responsable (→ Fiche 5 · Escalade).

4. Diagnostic pas à pas

  1. Alerte dans le navigateur avec numéro de téléphone ?

    SI → fermer le navigateur (Gestionnaire des tâches), ne rien appeler ; vérifier qu'aucun logiciel d'accès à distance n'a été installé.

    SINON → étape 2.

  2. Fichiers chiffrés + note de rançon ?

    SI → isolement, ne rien effacer (preuves), escalade immédiate, restauration depuis sauvegarde hors ligne après nettoyage complet (réinstallation).

    SINON → étape 3.

  3. Paramètres → Applications → Applications installées, trier par date ; extensions du navigateur ; Gestionnaire des tâches → Démarrage.
  4. Sécurité Windows → Protection contre les virus et menaces → Options d'analyse → « Analyse complète », puis « Analyse hors connexion Microsoft Defender » (redémarre et analyse hors de Windows).

5. Test de confirmation

Détections dans l'historique de protection ; comportement disparu après nettoyage. Limite : une analyse propre n'exclut pas une compromission (voleur d'identifiants déjà passé) → changer les mots de passe.

6. Correction

Désinstaller les programmes indésirables, supprimer les extensions, réinitialiser le navigateur ; mise en quarantaine/suppression par l'antivirus ; changer les mots de passe depuis un appareil sain ; activer l'authentification à deux facteurs ; si compromission profonde ou rançongiciel : sauvegarde des données (non exécutables), réinstallation propre (P6.4), restauration depuis une sauvegarde antérieure saine.

7. Validation

  • Analyse complète propre, protection en temps réel active, MAJ faites, navigateur normal, utilisateur sensibilisé (rapport).

8. Réponse d'examen modèle

Réponse rédigée attendue

Le poste affiche des publicités et la page d'accueil a changé depuis l'installation d'un convertisseur PDF gratuit. Je déconnecte le poste du réseau, j'identifie dans les applications installées deux logiciels ajoutés à la même date et une extension de navigateur inconnue, je les supprime, je réinitialise les paramètres du navigateur, puis je lance une analyse complète et une analyse hors connexion Microsoft Defender. Validation : analyse propre, page d'accueil normale. Je conseille à l'utilisateur de changer ses mots de passe depuis un autre appareil et je le sensibilise aux téléchargements.

Perd des points : rester connecté au réseau ; payer la rançon ; éteindre/réinstaller sans prévenir ni préserver les données ; installer un « antivirus miracle ».

9. Pièges et variantes

  • Lenteur ≠ virus par défaut : mesurer d'abord (P4.1).
