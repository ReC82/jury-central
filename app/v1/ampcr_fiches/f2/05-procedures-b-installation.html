3.B Procédures — Installation de Windows et de Linux

Avant toute installation (rappel en une ligne, détail en Fiche 5) : accord écrit, inventaire (modèle, CPU, RAM, disque, licence/édition), sauvegarde vérifiée, pilotes réseau/stockage du fabricant sur clé, clé BitLocker si chiffré. Création/suppression/formatage de partitions : → Fiche 1 · Partitionnement.

Ordre de contrôle d'une installation réussie (à recopier en fin de réponse)

Média officiel + empreinte SHA-256 vérifiée
 -> firmware : UEFI, Secure Boot, TPM (Win 11), mode SATA noté
 -> démarrage ponctuel "UEFI: clé USB"
 -> disque cible identifié (taille, modèle) -- jamais "le premier"
 -> installation (GPT : ESP + MSR + Windows + récupération ;
                  Linux : ESP + / [+ /home] [+ swap])
 -> compte(s), réseau, mises à jour, pilotes fabricant
 -> Gestionnaire de périphériques sans triangle / lspci -nnk
 -> activation, protection (antivirus, point de restauration)
 -> tests : son, réseau, impression, USB, veille ; rapport

P2.1 — La clé USB d'installation n'apparaît pas ou ne démarre pas

Fréquence : très fréquent · Gravité : bloquante pour l'intervention, sans risque

1. Symptômes observables

  • La clé n'est pas dans le menu de démarrage ponctuel ; ou elle est listée mais le PC démarre l'ancien système ; ou écran noir/curseur.
  • Installateur Windows : « Un pilote de média requis pour votre ordinateur est manquant » ; Linux : « Verification failed: (0x1A) Security Violation ».

2. Causes possibles (classées)

  1. ISO copiée comme un fichier sur la clé (non démarrable) — préparation.
  2. Fast Boot/« Ultra Fast » du firmware qui n'initialise pas l'USB ; port USB frontal/hub — configuration/matériel.
  3. Clé formatée pour un mode (MBR/hérité) et firmware en UEFI only, ou inversement — préparation.
  4. Secure Boot qui refuse un chargeur non signé (vieille ISO Linux, outil tiers) — sécurité.
  5. Image corrompue (téléchargement interrompu), clé défaillante.

3. Questions initiales et sécurité

  • Comment la clé a-t-elle été créée (outil de création de support de Microsoft, Rufus, Ventoy, dd, Disques d'Ubuntu, Etcher) ? Empreinte vérifiée ?
  • Créer la clé efface la clé : vérifier qu'elle ne contient rien d'utile.

4. Diagnostic pas à pas

  1. Brancher la clé sur un port USB arrière (carte mère), menu ponctuel (F12/F11/F8/Échap).

    SI elle apparaît maintenant → port/hub en cause.

    SINON → étape 2.

  2. Setup firmware : désactiver Fast Boot, vérifier que l'USB est autorisé au démarrage.

    SI la clé apparaît → réglage en cause (le remettre après installation si souhaité).

    SINON → étape 3.

  3. Vérifier la clé sur un autre PC : contient-elle \efi\boot\bootx64.efi (et \sources\install.wim/.esd pour Windows) ?

    SI elle ne contient qu'un fichier .iso → recréer la clé avec un outil de création (pas une copie).

    SINON → vérifier l'empreinte de l'ISO : certutil -hashfile fichier.iso SHA256 (Windows) / sha256sum fichier.iso (Linux), à comparer à la valeur publiée.

  4. Clé listée mais refusée (Security Violation) → ISO plus récente (shim signé) ; sinon désactivation temporaire de Secure Boot (attention BitLocker sur les autres disques).

5. Test de confirmation

Une clé recréée depuis une ISO à l'empreinte conforme démarre sur le port arrière. Limite : un port qui marche pour une clé peut refuser une autre (clé USB 3 sur vieux firmware).

6. Correction

Recréer la clé (outil de création de support Microsoft / Rufus en schéma GPT pour UEFI ; Ubuntu : Disques → Restaurer l'image, ou sudo dd if=ubuntu.iso of=/dev/sdX bs=4M status=progress conv=fsync).

Attention dd écrase sans confirmation le périphérique désigné : of=/dev/sdX doit être la clé (vérifiée par lsblk : taille, modèle, branchement/débranchement), jamais le disque du PC. Alternative prudente : outil graphique qui ne liste que les supports amovibles.

7. Validation

  • L'installateur s'affiche ; en UEFI, l'entrée choisie était « UEFI: nom de la clé » (sinon l'installation se fera en mode hérité, P2.4).

8. Réponse d'examen modèle

Réponse rédigée attendue

La clé n'est pas proposée au démarrage. Je vérifie d'abord ce qui est simple et réversible : port USB arrière, menu de démarrage ponctuel, désactivation du démarrage rapide du firmware. La clé reste absente ; contrôlée sur un autre PC, elle ne contient qu'un fichier ISO : elle n'a pas été rendue démarrable. Je vérifie l'empreinte SHA-256 de l'ISO officielle (certutil -hashfile), je recrée la clé avec l'outil de création de support, puis je démarre sur l'entrée « UEFI: » de la clé. Validation : l'installateur s'affiche en mode UEFI.

9. Pièges et variantes

  • « Un pilote de média requis est manquant » : très souvent média/clé défectueux ou port USB 3 non géré, rarement un vrai pilote à fournir → autre clé, autre port, recréer.
  • Deux entrées pour la même clé (« UEFI: Kingston » et « Kingston ») : le choix décide du mode d'installation.

P2.2 — « Ce PC ne peut pas exécuter Windows 11 » (prérequis TPM, Secure Boot, UEFI, CPU)

Fréquence : très fréquent · Gravité : bloquante pour la mise à niveau

1. Symptômes observables

  • Application Contrôle d'intégrité du PC : « Ce PC ne répond pas actuellement à la configuration système requise pour Windows 11 », avec le critère (TPM 2.0, démarrage sécurisé, processeur, RAM, stockage).
  • Installateur : « Ce PC ne peut pas exécuter Windows 11 ».

2. Causes possibles (classées)

  1. TPM présent dans le CPU (Intel PTT / AMD fTPM) mais désactivé dans le firmware — configuration.
  2. Secure Boot désactivé ou mode hérité (CSM) actif → disque MBR — configuration.
  3. Processeur hors liste, RAM < 4 Go, disque < 64 Go, TPM 1.2 seulement — matériel (non corrigeable par réglage).

3. Questions initiales et sécurité

  • Édition et licence actuelles ; BitLocker actif (changer Secure Boot/mode déclenche la demande de clé) ; sauvegarde avant conversion MBR→GPT.

4. Diagnostic pas à pas

  1. msinfo32 → « Mode BIOS » (UEFI/Hérité), « État du démarrage sécurisé » (Activé/Désactivé/Non pris en charge), processeur, mémoire installée.
  2. tpm.msc → « Le module de plateforme sécurisée est prêt à être utilisé », « Version de la spécification : 2.0 ». « Impossible de trouver le module TPM compatible » → TPM désactivé ou absent.

    SI TPM introuvable → setup firmware : activer Intel PTT / AMD fTPM (Security).

    SINON → étape 3.

  3. Mode BIOS = Hérité ?

    SI oui → disque MBR : le convertir en GPT sans perte avec mbr2gpt (ci-dessous), puis firmware en UEFI, puis activer Secure Boot.

    SINON (UEFI, Secure Boot désactivé) → activer Secure Boot (clés par défaut / « Standard »).

  4. Processeur non pris en charge / RAM insuffisante → pas de réglage : rester sous Windows 10 (fin du support grand public le 14/10/2025, mises à jour de sécurité étendues payantes/ESU), proposer Linux, ou un matériel compatible. Ne pas contourner les prérequis sur un poste professionnel.
C:\> mbr2gpt /validate /allowFullOS
C:\> mbr2gpt /convert /allowFullOS
MBR2GPT: Validation completed successfully
...
MBR2GPT: Conversion completed successfully
MBR2GPT: Before the new system can boot properly you need to switch the firmware to boot to UEFI mode!

Attention mbr2gpt /convert réécrit la table de partitions (sans effacer les données). Prérequis : sauvegarde vérifiée, /validate réussi (au plus 3 partitions principales sur le disque, pas de partition étendue), BitLocker suspendu, puis passage du firmware en UEFI immédiatement après. Alternative prudente : installation propre en UEFI après sauvegarde, ou rester en Windows 10.

5. Test de confirmation

Contrôle d'intégrité du PC : « Ce PC répond à la configuration requise pour Windows 11 ». Limite : la vérification porte sur l'état actuel ; une remise à zéro du firmware peut tout redésactiver.

6. Correction

Activer TPM et Secure Boot ; conversion GPT + UEFI si hérité ; sinon décision documentée avec le client (matériel non compatible).

7. Validation

  • msinfo32 : UEFI, démarrage sécurisé activé ; tpm.msc : prêt, 2.0 ; mise à niveau proposée ; démarrage normal après conversion.

8. Réponse d'examen modèle

Réponse rédigée attendue

Relevé msinfo32 : Mode BIOS hérité, démarrage sécurisé non pris en charge, processeur de 10e génération (compatible), 16 Go. tpm.msc : aucun TPM. Conclusion : le matériel est compatible mais trois réglages bloquent. Plan : 1) sauvegarde vérifiée ; 2) activer Intel PTT dans le firmware ; 3) mbr2gpt /validate /allowFullOS puis /convert ; 4) passer le firmware en UEFI, activer Secure Boot ; 5) vérifier msinfo32 et l'application Contrôle d'intégrité du PC, puis lancer la mise à niveau. Je ne contourne pas les prérequis.

Perd des points : « acheter un nouveau PC » sans lire msinfo32 ; activer UEFI sans convertir le disque (le PC ne démarre plus : P1.1).

9. Pièges et variantes

  • « Démarrage sécurisé : non pris en charge » dans msinfo32 = PC en mode hérité, pas forcément matériel incapable.
  • Machine virtuelle : ajouter un TPM virtuel et le firmware UEFI dans l'hyperviseur.

P2.3 — « Nous n'avons trouvé aucun lecteur » : l'installateur ne voit pas le disque

Fréquence : fréquent (portables Intel récents) · Gravité : bloquante

1. Symptômes observables

  • Écran « Où souhaitez-vous installer Windows ? » vide : « Nous n'avons trouvé aucun lecteur. Pour obtenir un pilote de stockage, cliquez sur Charger un pilote. »
  • Installateur Ubuntu : aucun disque proposé, ou message demandant de désactiver Intel RST.

2. Causes possibles (classées)

  1. Contrôleur en mode Intel RST/VMD ou RAID sans pilote dans l'installateur — configuration/pilote.
  2. Disque non détecté par le firmware — matériel (Fiche 1).
  3. Disque présent mais verrouillé/hors ligne (rare).

3. Questions initiales et sécurité

  • Le disque contient-il des données ? Un RAID réel est-il configuré (deux disques) ?

4. Diagnostic pas à pas

  1. Setup firmware : le disque est-il listé ?

    SI non → → Fiche 1 · Stockage non détecté.

    SINON → étape 2.

  2. Mode du contrôleur : « RAID/Intel RST Premium », « VMD Controller : Enabled » ?

    SI oui → « Charger un pilote » : pilote Intel RST/« F6 » du fabricant (dossier décompressé sur une clé), puis Actualiser.

    SINON → Maj+F10 dans l'installateur, diskpart → list disk (lecture) : disque « Hors connexion » ou absent ?

  3. Linux : pas de pilote à charger → passer le contrôleur en AHCI / désactiver VMD, seulement si aucun Windows existant n'en dépend (sinon P1.4).

5. Test de confirmation

Après chargement du pilote, le disque apparaît avec sa taille réelle. Limite : le pilote doit correspondre à la génération de la plate-forme.

6. Correction

Charger le pilote du fabricant (préférable : ne change rien au firmware) ; ou désactiver VMD/RAID sur une machine vierge sans grappe.

Attention Passer de RAID à AHCI sur un PC qui a un Windows installé → INACCESSIBLE_BOOT_DEVICE (P1.4) ; sur une vraie grappe RAID → données illisibles. Prérequis : sauvegarde, savoir s'il existe un RAID. Alternative : charger le pilote.

7. Validation

  • Disque visible, installation menée, Gestionnaire de périphériques → Contrôleurs de stockage sans erreur.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le SSD est listé dans le firmware (pas de panne matérielle) mais l'installateur Windows ne le voit pas ; le contrôleur est en mode Intel VMD. L'installateur ne contient pas ce pilote. Je télécharge le pilote Intel RST du fabricant du portable sur une seconde clé, je clique sur « Charger un pilote », je sélectionne le dossier ; le disque apparaît. Je poursuis l'installation sur ce disque identifié par sa taille. Je ne modifie pas le mode du contrôleur, ce qui évite tout effet sur le démarrage.

9. Pièges et variantes

  • Disque visible mais pas de bouton Suivant : « Windows ne peut pas être installé sur ce disque » → P2.4.

P2.4 — « Windows ne peut pas être installé sur ce disque » (GPT / MBR)

Fréquence : fréquent · Gravité : bloquante, risque de perte de données si mal corrigée

1. Symptômes observables

  • « Windows ne peut pas être installé sur ce disque. Le disque sélectionné est de style de partition GPT. » (clé démarrée en mode hérité).
  • « Windows ne peut pas être installé sur ce disque. Le disque sélectionné contient une table de partition MBR. Sur les systèmes EFI, Windows ne peut être installé que sur des disques GPT. » (clé démarrée en UEFI).

2. Causes possibles (classées)

  1. Clé démarrée dans le mauvais mode par rapport au disque — manipulation.
  2. Disque réutilisé (ancien PC hérité) — préparation.

3. Questions initiales et sécurité

  • Le disque contient-il des données à conserver ? Accord pour effacer ? Le PC (et Windows 11) exige-t-il l'UEFI ?

4. Diagnostic pas à pas

  1. Quel mode voulu ? Windows 11 / PC récent → UEFI + GPT.
  2. Redémarrer et choisir l'entrée « UEFI: clé » dans le menu ponctuel (ou désactiver CSM).

    SI le disque est GPT → l'installation passe.

    SINON (disque MBR) → étape 3.

  3. Disque MBR en UEFI : s'il porte des données → les sauvegarder d'abord ; s'il porte un Windows à conserver → mbr2gpt depuis ce Windows (P2.2) ; s'il est à effacer (accord écrit) → supprimer les partitions dans l'installateur, l'installateur crée alors un GPT.

Attention La solution « Maj+F10, diskpart, select disk 0, clean, convert gpt » efface tout le disque sélectionné. Prérequis : sauvegarde vérifiée, accord écrit, disque identifié par list disk (taille, n°), clés USB de données débranchées. Alternative prudente : démarrer la clé dans le mode du disque, ou mbr2gpt (sans perte). Détail du partitionnement : → Fiche 1 · Partitionnement.

5. Test de confirmation

Le bouton Suivant devient actif. Après installation : msinfo32 → UEFI.

6. Correction

Démarrer la clé dans le bon mode ; sinon conversion sans perte ; effacement en dernier, avec accord.

7. Validation

  • Partitions créées : ESP (FAT32 ~100 Mo), MSR (16 Mo), Windows (NTFS), récupération ; démarrage par « Windows Boot Manager ».

8. Réponse d'examen modèle

Réponse rédigée attendue

Le message indique un disque MBR alors que la clé a démarré en UEFI. Le disque provient de l'ancien PC et contient des photos du client. Je n'efface rien : je sauvegarde d'abord les photos (copie vérifiée), puis, avec l'accord écrit du client, je supprime les anciennes partitions dans l'installateur pour qu'il crée une table GPT en UEFI. Validation : installation terminée, msinfo32 « Mode BIOS : UEFI », photos restaurées et ouvertes avec le client.

Perd des points : clean sans sauvegarde ni accord ; repasser le firmware en hérité pour un Windows 11.

9. Pièges et variantes

  • « Windows ne peut pas être installé sur ce disque. Il se peut que le matériel de cet ordinateur ne prenne pas en charge le démarrage sur ce disque » → contrôleur en mode non démarrable, ordre de démarrage, ou disque USB externe choisi comme cible.

P2.5 — L'installation échoue en cours de copie (0x8007025D, 0x80070570, redémarrage en boucle)

Fréquence : moyen · Gravité : bloquante, révèle parfois un matériel instable

1. Symptômes observables

  • « Windows ne peut pas installer les fichiers requis. Assurez-vous que tous les fichiers requis pour l'installation sont disponibles, puis redémarrez l'installation. Code d'erreur : 0x8007025D » ; 0x80070570 (fichier endommagé/illisible) ; « Windows n'a pas pu terminer l'installation » ; écran bleu pendant l'installation.

2. Causes possibles (classées)

  1. Image/clé corrompue — média.
  2. Port/clé USB instable — matériel périphérique.
  3. RAM instable (XMP/EXPO trop agressif, barrette) — matériel.
  4. Disque cible défaillant — matériel.

3. Questions initiales et sécurité

  • Échoue toujours au même pourcentage ? Profil mémoire XMP activé ?

4. Diagnostic pas à pas

  1. Recréer la clé à partir d'une ISO dont l'empreinte est vérifiée, sur une autre clé, port arrière.

    SI l'installation passe → média.

    SINON → étape 2.

  2. Désactiver XMP/EXPO, ne garder qu'une barrette, test mémoire (→ Fiche 1 · RAM).

    SI passe → mémoire.

    SINON → SMART/autre disque (Fiche 1).

5. Test de confirmation

La modification d'un seul facteur fait réussir l'installation. Limite : une erreur mémoire intermittente peut passer une fois ; test mémoire complet.

6. Correction

Nouveau média ; mémoire à sa fréquence standard / barrette remplacée ; disque remplacé.

7. Validation

  • Installation complète, sfc /scannow → « aucune violation d'intégrité », pas de BugCheck dans le journal.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le code 0x8007025D survient pendant la copie des fichiers : l'installateur lit des données incohérentes. Causes à tester, de la plus simple : média, port USB, mémoire, disque. Je recrée la clé depuis l'ISO officielle (empreinte vérifiée) sur une autre clé ; l'erreur persiste. Je désactive le profil XMP et teste avec une seule barrette : l'installation réussit. Le test mémoire de la seconde barrette signale des erreurs : elle est à remplacer (Fiche 1). Validation : installation complète, SFC sans violation.

9. Pièges et variantes

  • Même code avec un disque presque plein de partitions anciennes : peu probable, l'erreur est de lecture.

P2.6 — Installation de Linux : session live, double démarrage, partitions

Fréquence : fréquent · Gravité : moyenne à critique (double démarrage = risque pour Windows et ses données)

1. Symptômes observables

  • Session live en écran noir ; installateur qui refuse le double démarrage (« BitLocker est activé », « Intel RST ») ; aucune option « Installer à côté de Windows » ; après installation, Windows absent ou Linux absent (P1.5).

2. Causes possibles (classées)

  1. Carte graphique (pilote libre inadapté) → option « Safe graphics »/nomodeset.
  2. BitLocker/Chiffrement de l'appareil actif : l'installateur ne peut pas réduire la partition.
  3. Intel RST/VMD (P2.3).
  4. Pas d'espace non alloué ; Windows en hérité et live en UEFI (ou l'inverse).

3. Questions initiales et sécurité

  • Sauvegarde de Windows et des données ; clé BitLocker récupérée ; Démarrage rapide de Windows désactivé ; mode de Windows relevé (msinfo32).

4. Diagnostic pas à pas

  1. Depuis Windows : msinfo32 (Mode BIOS) et manage-bde -status.

    SI chiffré → déchiffrer ou suspendre selon la distribution et l'accord du client ; garder la clé.

    SINON → étape 2.

  2. Réduire la partition Windows depuis Windows (Gestion des disques → clic droit sur C: → Réduire le volume) : l'outil de Windows connaît NTFS. → espace non alloué (détail : Fiche 1).
  3. Démarrer la live dans le MÊME mode que Windows (« UEFI: clé »), tester Wi-Fi, son, écran, puis « Installer à côté de Windows » ou partitionnement manuel : ESP existante réutilisée (point de montage /boot/efi, sans formater), / ext4 (25–50 Go mini), /home séparé facultatif, swap selon RAM/hibernation (un fichier swap suffit sur Ubuntu).

Attention Dans le partitionnement manuel, cocher « formater » sur l'ESP efface le chargeur de Windows ; choisir la partition Windows comme / efface Windows. Prérequis : sauvegarde, schéma des partitions noté avant (lsblk -f dans la live). Alternative prudente : Linux dans une machine virtuelle ou sur un disque séparé.

5. Test de confirmation

GRUB propose les deux systèmes ; chacun démarre ; Windows ne signale pas d'erreur de disque.

6. Correction

Selon blocage : nomodeset, BitLocker, RST, mode de démarrage, puis P1.5 si GRUB manque.

7. Validation

  • lsblk -f conforme au plan ; sudo apt update && sudo apt upgrade ; pilotes (ubuntu-drivers devices) ; réseau, son, impression ; utilisateur dans le groupe sudo si administrateur.

8. Réponse d'examen modèle

Réponse rédigée attendue

Plan de double démarrage Windows 11 + Ubuntu : 1) accord écrit et sauvegarde complète ; 2) relevé msinfo32 (UEFI) et état BitLocker (clé récupérée) ; désactivation du démarrage rapide ; 3) réduction de C: par la Gestion des disques pour libérer 80 Go ; 4) démarrage de la clé Ubuntu (empreinte vérifiée) sur l'entrée UEFI, test en session live ; 5) « Installer Ubuntu à côté de Windows » ; l'ESP existante est réutilisée sans formatage ; 6) contrôle : GRUB affiche les deux systèmes, chacun démarre, données Windows intactes ; mises à jour et pilotes ; rapport.

9. Pièges et variantes

  • Créer une 2e ESP sur le même disque : inutile, source de confusion.
  • Heure décalée de 1–2 h entre Windows et Linux : Linux stocke l'horloge en UTC ; timedatectl set-local-rtc 1 ou laisser l'heure se synchroniser (comportement normal, pas une panne).

P2.7 — Windows non activé après installation ou réparation

Fréquence : moyen · Gravité : faible (fonctionnel, personnalisation limitée), mais conformité

1. Symptômes observables

  • Filigrane « Activer Windows » ; Paramètres → Système → Activation (Windows 11) ou Mise à jour et sécurité → Activation (Windows 10) : 0xC004F213 « Windows a signalé qu'aucune clé de produit n'a été trouvée sur votre appareil », 0x803F7001, 0xC004F050 (clé non valide).

2. Causes possibles (classées)

  1. Édition installée ≠ édition de la licence (Pro installé, licence Famille OEM) — installation.
  2. Carte mère remplacée (licence numérique liée au matériel) — matériel.
  3. Pas encore de connexion Internet — réseau.
  4. Clé de volume/entreprise hors domaine — licence.

3. Questions initiales et sécurité

  • Type de licence : OEM (clé dans le firmware), boîte (Retail), numérique liée au compte Microsoft, volume.

4. Diagnostic pas à pas

  1. slmgr /dli (édition, canal, 5 derniers caractères de la clé) et slmgr /xpr.
  2. Clé OEM dans le firmware (PowerShell admin) : (Get-CimInstance SoftwareLicensingService).OA3xOriginalProductKey.

    SI clé Famille et Windows Pro installé → réinstaller l'édition Famille (ou acheter la mise à niveau Pro).

    SINON carte mère changée → Activation → Résolution des problèmes → « J'ai changé de matériel sur cet appareil récemment » (compte Microsoft lié).

5. Test de confirmation

Après correction : « Windows est activé avec une licence numérique ». Limite : une licence OEM ne se transfère pas sur un autre PC.

6. Correction

Bonne édition ; clé valide (Modifier la clé de produit) ; résolution des problèmes d'activation ; jamais d'outil de « crack ».

7. Validation

  • slmgr /xpr : « La machine est activée de manière permanente. »

8. Réponse d'examen modèle

Réponse rédigée attendue

L'activation échoue (0xC004F213) après la réinstallation. slmgr /dli montre Windows 11 Professionnel ; la clé OEM du firmware est une clé Famille. L'édition installée ne correspond pas à la licence. Je réinstalle l'édition Famille (sauvegarde faite) ou, si le client a besoin de Pro, je lui propose une licence de mise à niveau. Validation : « Windows est activé ».

9. Pièges et variantes

  • L'installateur choisit automatiquement l'édition de la clé OEM : installer « Pro » sans clé Pro mène à ce cas.
