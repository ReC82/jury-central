3.E Procédures — Comptes, droits, profils, espace disque, système de fichiers

P5.1 — « Vous devez disposer d'autorisations d'administrateur » : installer, modifier sans rendre l'utilisateur administrateur

Fréquence : très fréquent · Gravité : faible (fonctionnement normal de la sécurité)

1. Symptômes observables

  • Invite du Contrôle de compte d'utilisateur (UAC) qui demande un nom et un mot de passe administrateur (compte standard) ; « Vous devez disposer d'autorisations d'administrateur pour… » ; « Accès refusé » dans C:\Program Files, C:\Windows.
  • Linux : E: Could not open lock file /var/lib/dpkg/lock-frontend - open (13: Permission denied) → commande lancée sans sudo.

2. Causes possibles (classées)

  1. Compte standard (comportement voulu, moindre privilège) — compte.
  2. Action qui modifie le système pour tous — droits.
  3. Commande Linux lancée sans sudo — utilisateur.

3. Questions initiales et sécurité

  • Le logiciel est-il autorisé/licencié par l'organisation ? Qui est administrateur du poste ?

4. Diagnostic pas à pas

  1. whoami et net user nom (« Appartient aux groupes locaux : *Utilisateurs » ou « *Administrateurs ») ; Linux : id (groupe sudo ou wheel ?).

    SI compte standard et installation légitime → l'administrateur saisit ses identifiants dans l'invite UAC (élévation ponctuelle).

    SINON SI compte admin et « Accès refusé » quand même → droits NTFS du dossier (onglet Sécurité) ou fichier utilisé/protégé.

  2. Besoin récurrent (logiciel métier qui doit écrire dans son dossier) → droit Modifier ciblé sur ce dossier pour l'utilisateur/groupe concerné, pas l'appartenance au groupe Administrateurs.
C:\> net user julie
C:\> net localgroup Administrateurs
C:\> whoami /groups
Nom d'utilisateur                   julie
Compte : actif                      Oui
Le mot de passe expire              Jamais
Dernier accès                       27/10/2026 08:41:13
Appartient aux groupes locaux       *Utilisateurs
La commande s'est terminée correctement.

5. Test de confirmation

L'action réussit avec élévation ponctuelle, le compte reste standard (net user).

6. Correction

Élévation par un admin ; droits ciblés ; jamais de désactivation de l'UAC (Panneau de configuration → Comptes d'utilisateurs → Modifier les paramètres de contrôle de compte d'utilisateur : laisser le niveau par défaut).

7. Validation

  • Logiciel fonctionne avec le compte standard ; groupe Administrateurs inchangé.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le message UAC est normal : Julie utilise un compte standard (vérifié par net user julie : groupe Utilisateurs). C'est le principe du moindre privilège, qui limite l'effet d'un logiciel malveillant. Après vérification que le logiciel est autorisé, je saisis moi-même les identifiants administrateur dans l'invite pour l'installer ; Julie reste en compte standard. Je teste le logiciel avec sa session.

Perd des points : ajouter l'utilisateur au groupe Administrateurs ; désactiver l'UAC ; communiquer le mot de passe administrateur.

9. Pièges et variantes

  • Le groupe s'appelle « Administrateurs » sur un Windows français, « Administrators » en anglais : net localgroup sans argument liste les noms exacts.
  • Un administrateur doit aussi « Exécuter en tant qu'administrateur » une invite de commandes (jeton filtré par l'UAC) pour sfc, DISM, chkdsk /f.

P5.2 — Mot de passe oublié, compte verrouillé ou désactivé (Windows local, compte Microsoft, Linux)

Fréquence : très fréquent · Gravité : moyenne (accès aux données)

1. Symptômes observables

  • « Le mot de passe est incorrect. Veuillez réessayer. » ; « Le compte référencé est actuellement verrouillé et ne peut pas être utilisé pour ouvrir une session » ; « Votre compte a été désactivé. Contactez votre administrateur système. »

2. Causes possibles (classées)

  1. Verr Maj / disposition clavier (QWERTY/AZERTY) / PIN confondu avec le mot de passe — utilisateur.
  2. Oubli — utilisateur.
  3. Verrouillage après X tentatives (stratégie de verrouillage) — sécurité.
  4. Compte désactivé par un admin — configuration.

3. Questions initiales et sécurité

  • Identité et autorisation : la personne est-elle bien le titulaire / mandatée par le responsable ?
  • Compte local ou compte Microsoft (adresse e-mail à l'écran) ? Un autre compte admin existe-t-il ?

4. Diagnostic pas à pas

  1. Vérifier Verr Maj, la langue du clavier (icône FRA/ENG), afficher le mot de passe (œil), essayer le mot de passe au lieu du PIN (« Options de connexion »).
  2. Compte Microsoft → « J'ai oublié mon mot de passe » sur l'écran, ou réinitialisation en ligne depuis un autre appareil.
  3. Compte local : questions de sécurité si définies ; sinon un administrateur réinitialise : net user nom * (saisie masquée), ou lusrmgr.msc (Pro), ou Paramètres → Comptes → Autres utilisateurs.

    SI « verrouillé » → attendre la durée de verrouillage ou, admin : net user nom /active:yes ne déverrouille pas, utiliser lusrmgr.msc → Propriétés → décocher « Le compte est verrouillé ».

    SINON SI « désactivé » → net user nom /active:yes après accord du responsable.

  4. Linux : un autre utilisateur sudo : sudo passwd nom ; sinon GRUB → recovery mode → root → mount -o remount,rw / → passwd nom. Verrouillage (faillock) : sudo faillock --user nom --reset.

Attention Réinitialiser le mot de passe d'un compte local Windows par un administrateur fait perdre l'accès aux fichiers chiffrés EFS de l'utilisateur et à ses identifiants enregistrés (Gestionnaire d'identification). Prérequis : accord du titulaire, information sur la perte. Alternative : le titulaire retrouve le mot de passe / disque de réinitialisation de mot de passe créé auparavant.

5. Test de confirmation

Connexion réussie ; documents et messagerie accessibles.

6. Correction

Réinitialisation par la voie officielle ; nouveau mot de passe choisi par l'utilisateur (« L'utilisateur doit changer de mot de passe à la prochaine ouverture de session » si l'admin l'a saisi).

7. Validation

  • Connexion, données présentes ; trace dans le rapport (qui a autorisé, quand).

8. Réponse d'examen modèle

Réponse rédigée attendue

Je vérifie d'abord l'identité de la personne et l'accord du responsable. Je contrôle Verr Maj et la langue du clavier. Le compte est local ; je me connecte avec le compte administrateur du poste et réinitialise le mot de passe par net user marc *, en ayant informé Marc que ses fichiers chiffrés EFS et mots de passe enregistrés pourraient être perdus, et je coche le changement obligatoire à la prochaine connexion. Validation : Marc se connecte, choisit son mot de passe, ses documents sont présents.

Perd des points : outils de « crack » ; réinitialiser sans vérifier l'identité ; confondre PIN et mot de passe.

9. Pièges et variantes

  • « Votre PIN n'est plus disponible » après changement de matériel : se connecter avec le mot de passe puis recréer le PIN.
  • Poste de domaine : réinitialisation par l'administrateur du domaine (Fiche 4).

P5.3 — « Vous êtes connecté avec un profil temporaire »

Fréquence : moyen · Gravité : élevée (risque de perte du travail de la session)

1. Symptômes observables

  • Notification « Vous êtes connecté avec un profil temporaire. Vous ne pouvez pas accéder à vos fichiers et les fichiers créés dans ce profil seront supprimés lorsque vous vous déconnecterez. » ; bureau vierge ; journal Application, source User Profile Service, ID 1511 (profil introuvable), 1515 (profil sauvegardé utilisé), 1500 (ouverture impossible).

2. Causes possibles (classées)

  1. Fichier NTUSER.DAT abîmé (coupure pendant la déconnexion) — profil.
  2. Clé du registre ProfileList en double (SID et SID.bak) — registre.
  3. Disque plein / erreurs de système de fichiers — stockage.
  4. Antivirus qui verrouille le profil au démarrage — logiciel.

3. Questions initiales et sécurité

  • Prévenir l'utilisateur : ne rien enregistrer dans cette session. Sauvegarder C:\Users\nom (depuis un autre compte admin) avant toute réparation. Point de restauration / sauvegarde du registre.

4. Diagnostic pas à pas

  1. Redémarrer une fois (verrou temporaire par antivirus/indexation).

    SI profil normal → surveiller (journal).

    SINON → étape 2.

  2. Espace de C: et état du disque (chkdsk C: lecture) ; dir C:\Users : le dossier du profil existe-t-il, avec ses documents ?
  3. wmic useraccount get name,sid ou whoami /user (depuis la session temporaire) pour le SID ; regedit → HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList : deux clés S-1-5-21-…-1001 et S-1-5-21-…-1001.bak ?

    SI oui → réparation avancée de la clé (renommer, ProfileImagePath correct, State=0, RefCount=0) après export de la clé.

    SINON → solution prudente : nouveau profil.

Attention Modifier le registre peut empêcher toute ouverture de session : exporter la clé ProfileList avant (Fichier → Exporter), n'agir que sur le SID de l'utilisateur. Alternative prudente (recommandée à l'examen) : créer un nouveau compte/profil et y copier les données (Documents, Bureau, Images, favoris, fichiers de messagerie) depuis l'ancien dossier, sans copier NTUSER.DAT ni AppData en bloc.

5. Test de confirmation

Ouverture de session sans notification, bureau et documents de l'utilisateur présents ; plus d'événement 1511.

6. Correction

Nouveau profil + migration des données (ou réparation de la clé) ; reconfiguration messagerie/imprimantes ; ancien dossier conservé (renommé) jusqu'à validation.

7. Validation

  • Deux connexions/déconnexions sans message, données et applications vérifiées avec l'utilisateur ; journal propre.

8. Réponse d'examen modèle

Réponse rédigée attendue

Après une coupure de courant, Mme Lambert ouvre un profil temporaire (User Profile Service 1511). Je lui demande de ne rien enregistrer. Je vérifie l'espace disque et chkdsk C: (aucune erreur), puis que C:\Users\lambert contient bien ses documents. Je sauvegarde ce dossier sur un disque externe. Solution prudente : je crée un nouveau compte local, j'y copie Documents, Bureau, Images et les favoris, je reconfigure sa messagerie. L'ancien dossier est conservé renommé jusqu'à ce qu'elle confirme que rien ne manque. Validation : deux ouvertures de session normales.

Perd des points : supprimer l'ancien profil avant d'avoir copié les données ; modifier le registre sans export.

9. Pièges et variantes

  • Plusieurs utilisateurs touchés en même temps → disque/système, pas un profil.

P5.4 — Linux : « Permission denied », « nom is not in the sudoers file »

Fréquence : très fréquent · Gravité : faible à moyenne

1. Symptômes observables

  • bash: ./sauvegarde.sh: Permission denied ; cp: cannot create regular file '/srv/partage/x': Permission denied ; julie is not in the sudoers file. (selon la version de sudo, suivi de « This incident has been reported to the administrator. »).

2. Causes possibles (classées)

  1. Fichier copié avec sudo → appartient à root — propriétaire.
  2. Utilisateur absent du groupe propriétaire / droits du groupe insuffisants — groupe.
  3. Pas de droit x sur un script ou sur un dossier parent — droits.
  4. Utilisateur hors du groupe sudo (Debian/Ubuntu) / wheel (Fedora) — administration.
  5. Montage ro/noexec — montage.

3. Questions initiales et sécurité

  • L'utilisateur doit-il vraiment avoir ce droit (besoin métier, accord du responsable) ?

4. Diagnostic pas à pas

  1. id julie et ls -l (fichier) / ls -ld (dossier et parents : namei -l /srv/partage/x).
  2. Appliquer la règle : propriétaire ? sinon groupe ? sinon autres.

    SI propriétaire = root dans le /home de l'utilisateur → sudo chown -R julie:julie /home/julie/Documents (ce dossier seulement).

    SINON SI groupe compta avec rwx mais julie hors groupe → sudo usermod -aG compta julie, puis déconnexion/reconnexion. SINON SI script sans x → chmod u+x script.sh.

  3. sudoers : depuis un compte administrateur, sudo usermod -aG sudo julie (Fedora : wheel) ; vérifier groups julie ; effet à la reconnexion. Édition directe de /etc/sudoers : uniquement via sudo visudo (contrôle de syntaxe).
$ id julie
uid=1002(julie) gid=1002(julie) groups=1002(julie),100(users)
$ ls -l /srv/compta/bilan.ods
-rw-rw---- 1 marc compta 18432 oct. 26 17:02 /srv/compta/bilan.ods
  -> julie n'est ni marc ni membre de compta : catégorie "autres" = ---

Attention usermod -G sans -a remplace tous les groupes secondaires (l'utilisateur peut perdre sudo). Jamais chmod -R 777, jamais chown -R sur /, /etc, /usr ou tout /home. Alternative : droit minimal ciblé.

5. Test de confirmation

Après reconnexion : id montre le groupe ; l'action réussit en tant que julie (sudo -u julie touch /srv/compta/test pour tester) ; les autres utilisateurs n'ont pas gagné de droits.

6. Correction

Ajout au groupe, chown/chmod ciblés (ex. dossier partagé : chmod 2770 pour que les nouveaux fichiers héritent du groupe).

7. Validation

  • Test en tant que l'utilisateur ; ls -l final noté dans le rapport.

8. Réponse d'examen modèle

Réponse rédigée attendue

Julie reçoit « Permission denied » sur bilan.ods. ls -l : propriétaire marc, groupe compta, droits rw-rw---- (660). id julie : elle n'est pas membre de compta, donc la catégorie « autres » s'applique : aucun droit. Le responsable confirme qu'elle travaille à la comptabilité. Correction : sudo usermod -aG compta julie (avec -a pour conserver ses autres groupes), puis reconnexion. Validation : id julie montre compta, elle ouvre et enregistre le fichier. Je n'ai pas modifié les droits du fichier, ce qui aurait ouvert l'accès à d'autres.

Perd des points : chmod 777 ; oublier la reconnexion ; usermod -G sans -a.

9. Pièges et variantes

  • Droit w sur le fichier mais pas sur le dossier : on peut modifier le fichier mais pas le supprimer/renommer.
  • Dossier sans x pour l'utilisateur : impossible d'y entrer même avec r.

P5.5 — Windows : disque C: plein (« Espace disque insuffisant »)

Fréquence : très fréquent · Gravité : moyenne (MAJ bloquées, lenteur, profils)

1. Symptômes observables

  • Barre rouge dans l'Explorateur ; notification « Espace disque insuffisant » ; MAJ en 0x80070070 ; programmes qui ne peuvent plus enregistrer.

2. Causes possibles (classées)

  1. Fichiers temporaires, cache des MAJ, Windows.old (après mise à niveau, supprimé automatiquement après 10 jours) — système.
  2. Téléchargements, vidéos, synchronisation cloud (OneDrive « toujours conserver sur cet appareil ») — utilisateur.
  3. hiberfil.sys, pagefile.sys, points de restauration — système.
  4. Logiciel qui écrit en boucle (journaux, sauvegardes locales) — application.
  5. Petit SSD (128 Go) — matériel.

3. Questions initiales et sécurité

  • Rien de personnel n'est supprimé sans accord explicite ; déplacer plutôt que supprimer.

4. Diagnostic pas à pas

  1. Paramètres → Système → Stockage (Windows 10/11) : répartition par catégories.

    SI « Fichiers temporaires » important → Fichiers temporaires → cocher (en vérifiant « Téléchargements » avec l'utilisateur) → Supprimer.

    SINON SI « Autres » ou « Applications » → étape 2.

  2. Nettoyage de disque (cleanmgr) → « Nettoyer les fichiers système » : Nettoyage de Windows Update, Installations précédentes de Windows (si plus de retour arrière souhaité), Fichiers temporaires.
  3. Analyse des dossiers : Explorateur, tri par taille ; dossiers usuels (C:\Users\nom\Downloads, Videos, AppData\Local\Temp) ; dir C:\ /a pour les fichiers cachés à la racine.
  4. Composants (admin) : DISM /Online /Cleanup-Image /StartComponentCleanup.
  5. Hibernation : powercfg /h off supprime hiberfil.sys (désactive aussi le démarrage rapide et la veille prolongée) — seulement si non utilisés.

5. Test de confirmation

Espace libre mesuré avant/après (Propriétés de C:) ; la MAJ ou l'enregistrement qui échouait réussit.

6. Correction

Nettoyages ci-dessus ; déplacement des données personnelles vers D: / disque externe / cloud (accord) ; Assistant Stockage activé (Paramètres → Système → Stockage) ; corriger le logiciel qui remplit le disque ; disque plus grand si structurel (Fiche 1).

Attention Ne pas supprimer à la main dans C:\Windows, C:\Windows\WinSxS, C:\Windows\Installer, C:\ProgramData : Windows ou des logiciels deviennent irréparables. Utiliser les outils (Stockage, cleanmgr, DISM).

7. Validation

  • 15–20 % libres au minimum ; MAJ installées ; utilisateur informé de ce qui a été supprimé/déplacé (liste dans le rapport).

8. Réponse d'examen modèle

Réponse rédigée attendue

C: (SSD 256 Go) a 3 Go libres. Paramètres → Stockage : fichiers temporaires 14 Go, installation précédente de Windows 22 Go (mise à niveau de plus d'un mois, validée par l'utilisateur), Téléchargements 40 Go. Actions : nettoyage des fichiers système (cleanmgr), suppression de Windows.old, déplacement des téléchargements utiles sur le disque externe après tri avec l'utilisateur. Résultat : 79 Go libres. Assistant Stockage activé pour l'avenir. Validation : mise à jour mensuelle installée, utilisateur informé par écrit.

9. Pièges et variantes

  • Espace qui fond de nouveau en quelques jours → chercher le processus qui écrit (Moniteur de ressources → Disque).
  • Fichiers OneDrive : « Libérer de l'espace » (fichiers à la demande) plutôt que suppression (la suppression se synchronise).

P5.6 — Linux : « No space left on device », partition pleine

Fréquence : fréquent · Gravité : élevée (services, sessions, bases de données)

1. Symptômes observables

  • No space left on device à l'écriture ; services en échec ; session graphique impossible ; MAJ qui échouent.

2. Causes possibles (classées)

  1. Journaux qui grossissent (/var/log, journal systemd) — service bavard.
  2. Cache apt, anciens noyaux — paquets.
  3. Sauvegardes/fichiers volumineux accumulés — usage.
  4. Inodes épuisés (millions de petits fichiers : sessions PHP, cache) — système de fichiers.
  5. Fichier supprimé encore ouvert par un processus — processus.

3. Questions initiales et sécurité

  • Ne pas supprimer au hasard dans /var/lib, /usr, /etc ; pas de suppression de données client sans accord.

4. Diagnostic pas à pas

  1. df -h : quelle partition, Use%.

    SI Use% < 100 % mais message quand même → df -i (IUse% 100 % = inodes) → chercher le dossier aux millions de fichiers.

    SINON → étape 2.

  2. sudo du -xh -d1 / | sort -h puis descendre (/var, /var/log, /home).
  3. journalctl --disk-usage ; ls -lhS /var/log | head.
  4. Écart entre df et du → sudo lsof +L1 : fichier « (deleted) » encore ouvert → redémarrer le service qui le tient.
$ df -h /
Sys. de fichiers Taille Utilisé Dispo Uti% Monté sur
/dev/nvme0n1p2      49G     49G     0 100% /
$ sudo du -xh -d1 /var | sort -h | tail -3
1,2G    /var/cache
31G     /var/log
33G     /var
$ ls -lhS /var/log | head -3
-rw-r----- 1 syslog adm 27G oct. 27 09:40 syslog

5. Test de confirmation

Le fichier/dossier identifié explique l'essentiel de l'occupation ; sa croissance est observable (ls -lh à quelques minutes d'intervalle) ; le journal montre le message répété.

6. Correction

Libérer sans risque : sudo journalctl --vacuum-size=500M, sudo apt clean, sudo apt autoremove (lire la liste). Gros journal texte ouvert : le vider sans le supprimer (sudo truncate -s 0 /var/log/syslog) après en avoir gardé un extrait pour le diagnostic. Puis corriger la cause (service qui écrit en boucle, rotation logrotate, rétention des sauvegardes).

Attention rm d'un journal ouvert ne libère pas l'espace (fichier « deleted » tenu par le processus) ; rm -rf avec une variable vide ou un chemin approximatif peut détruire le système. Prérequis : chemin lu deux fois, copie de ce qui peut servir. Alternative : outils de la distribution (vacuum, apt clean, logrotate).

7. Validation

  • df -h < 80–90 % ; services relancés (systemctl --failed vide) ; croissance arrêtée le lendemain.

8. Réponse d'examen modèle

Réponse rédigée attendue

df -h : / à 100 %. du désigne /var/log/syslog (27 Go). Ce journal contient en boucle la même erreur d'un service d'impression. Je conserve les 1 000 dernières lignes pour le diagnostic, vide le fichier avec truncate, nettoie le journal systemd (journalctl --vacuum-size=500M) et le cache apt. Je corrige ensuite la cause : le service d'impression mal configuré, que je répare et redémarre. Validation : / à 42 %, services démarrés, plus de croissance anormale le lendemain.

Perd des points : supprimer sans identifier ; libérer l'espace sans corriger la cause ; ignorer df -i.

9. Pièges et variantes

  • /boot plein bloque les MAJ du noyau (P3.4).
  • Les 5 % réservés à root sur ext4 : un utilisateur voit « plein » alors que root peut encore écrire.

P5.7 — Système de fichiers abîmé : « Read-only file system », volume RAW « Vous devez formater le disque », erreurs NTFS

Fréquence : moyen · Gravité : élevée à critique (données)

1. Symptômes observables

  • Linux : Read-only file system ; dmesg : EXT4-fs error … remounting filesystem read-only, I/O error, dev sda, sector ….
  • Windows : « Vous devez formater le disque dans le lecteur E: avant de pouvoir l'utiliser » ; Gestion des disques : volume RAW ; journal Système Ntfs 55 (« structure du système de fichiers endommagée »), disk 7 (bloc défectueux), disk 153 (E/S réessayée), disk 51 (erreur de pagination).

2. Causes possibles (classées)

  1. Retrait sans éjection / coupure — logique.
  2. Disque/clé qui faiblit (secteurs) — matériel.
  3. Câble/port USB, alimentation — matériel.
  4. Démarrage rapide Windows (NTFS « sale » vu depuis Linux) — configuration.
  5. Volume BitLocker verrouillé vu comme RAW — chiffrement.

3. Questions initiales et sécurité

  • Les données ont-elles une copie ? Si non : priorité à la récupération, aucune réparation qui écrit avant copie/image du disque.
  • Bruit, lenteur extrême, SMART ? → Fiche 1 · Stockage.

4. Diagnostic pas à pas

  1. Refuser le formatage proposé (« Annuler »).
  2. Journaux : Windows → Système (disk 7/153, Ntfs 55) ; Linux → sudo dmesg -T | grep -iE 'I/O error|ext4|ata|nvme'.

    SI erreurs d'E/S matérielles (disk 7, « I/O error ») → disque suspect : copie des données (ou image) d'abord, SMART (Fiche 1), pas de chkdsk /r ni fsck avant la copie.

    SINON (erreurs logiques seulement) → étape 3.

  3. Autre port/câble, autre PC (externe). Volume BitLocker ? (manage-bde -status).
  4. Vérification en lecture : chkdsk E: ; Linux démonté : sudo fsck -n /dev/sdb1 (-n = ne rien modifier).

    SI erreurs → données copiées ? oui → chkdsk E: /f / sudo fsck -y /dev/sdb1 (démonté).

    SINON (RAW, chkdsk : « Le type du système de fichiers est RAW. CHKDSK n'est pas disponible pour les lecteurs RAW. ») → récupération de données (outil spécialisé, ou prestataire si précieux).

C:\> chkdsk E:
C:\> chkdsk E: /f
Windows a trouvé des problèmes dans le système de fichiers.
Exécutez CHKDSK avec l'option /F (fix) pour corriger ces problèmes.
...
Windows a corrigé le système de fichiers.
Aucune autre action n'est requise.

Attention chkdsk /f, chkdsk /r et fsck -y modifient le système de fichiers (fichiers orphelins déplacés dans found.000 / lost+found) ; /r sollicite fortement un disque faible. Le formatage efface l'index des fichiers. Prérequis : copie des données. Alternative prudente : lecture seule (chkdsk sans option, fsck -n), récupération d'abord.

5. Test de confirmation

Après réparation : volume monté en écriture, fichiers ouvrables, chkdsk/fsck -n sans erreur. Limite : une réparation logique réussie sur un disque qui a des secteurs défectueux n'est qu'un sursis.

6. Correction

Linux « Read-only » : copier ce qui est lisible, redémarrer sur live, fsck de la partition démontée, SMART ; Windows : chkdsk /f après copie ; disque défaillant : remplacement (Fiche 1).

7. Validation

  • Montage normal, données contrôlées avec l'utilisateur, journal sans nouvelle erreur pendant plusieurs jours.

8. Réponse d'examen modèle

Le disque externe affiche « Vous devez formater le disque » ; je refuse le formatage, qui rendrait la récupération plus difficile. Le journal Système ne montre pas d'erreur disk 7 (pas de secteurs défectueux signalés) mais une erreur Ntfs ; l'utilisateur a arraché le câble pendant une copie. Le disque n'a pas de copie ailleurs : je fais d'abord une image/copie avec un outil de récupération, puis je lance chkdsk E: /f. Validation : volume NTFS lisible, fichiers ouverts avec l'utilisateur ; conseil : éjection sécurisée et sauvegarde régulière.

Perd des points : accepter le formatage ; lancer chkdsk /r sur un disque qui claque avant d'avoir copié les données.
