3.C Procédures — Pilotes, écrans bleus, kernel panic, mises à jour, paquets

P3.1 — Périphérique inconnu, Code 28 : pas de son, pas de réseau, pas de Wi-Fi après installation

Fréquence : très fréquent · Gravité : moyenne (fonction absente)

1. Symptômes observables

  • devmgmt.msc : « Autres périphériques » → « Périphérique inconnu », « Contrôleur Ethernet », « Contrôleur de bus SM », « Périphérique PCI » avec triangle jaune ; Propriétés → Général → État : « Les pilotes de ce périphérique ne sont pas installés. (Code 28) ».
  • Linux : lspci -nnk montre le périphérique sans ligne « Kernel driver in use » ; dmesg : firmware: failed to load iwlwifi-….

2. Causes possibles (classées)

  1. Pilote absent de l'installation générique (chipset, Wi-Fi, lecteur de cartes) — pilote.
  2. Pas de réseau pour que Windows Update le télécharge (le pilote réseau lui-même manque) — dépendance.
  3. Firmware non libre non installé (Debian) — paquet.
  4. Périphérique très récent/ancien sans pilote pour cette version — compatibilité.

3. Questions initiales et sécurité

  • Modèle exact du PC (étiquette, msinfo32 → Modèle du système) ; source fiable = site du fabricant du PC ou du composant, Windows Update. Jamais de site « driver updater ».
  • Point de restauration avant installation de pilotes.

4. Diagnostic pas à pas

  1. Propriétés → Détails → Propriété « ID du matériel ». — attendu : PCI\VEN_8086&DEV_2725&SUBSYS_00248086 (VEN = fabricant de la puce, 8086 = Intel, 10EC = Realtek, 14E4 = Broadcom, 10DE = NVIDIA, 1002 = AMD) ou USB\VID_046D&PID_C52B.

    SI VEN/DEV identifiés → chercher le pilote de ce composant sur le site du fabricant du PC (modèle exact), sinon du fabricant de la puce.

    SINON (ID générique ACPI\…) → pack chipset/« Serial IO » du fabricant du PC.

  2. Pas de réseau ? Télécharger le pilote réseau sur un autre PC → clé USB ; ou partage de connexion USB d'un smartphone (pilote générique RNDIS) puis Windows Update → Options avancées → Mises à jour facultatives → Mises à jour de pilotes.
  3. Installer : exécutable du fabricant, ou Propriétés → Pilote → Mettre à jour le pilote → « Parcourir mon poste de travail » → dossier décompressé (fichier .inf).

    SI « Le meilleur pilote est déjà installé » alors que le triangle reste → mauvais dossier/architecture, voir Code affiché (P3.2).

    SINON redémarrer, valider.

  4. Linux : lspci -nnk / lsusb → IDs [8086:2725] ; sudo dmesg | grep -i firmware ; Ubuntu : ubuntu-drivers devices ; Debian : activer la section non-free-firmware et installer le paquet (ex. firmware-iwlwifi, firmware-realtek), puis redémarrer ou recharger le module (sudo modprobe -r iwlwifi && sudo modprobe iwlwifi).
$ lspci -nnk | grep -A3 -i network
02:00.0 Network controller [0280]: Intel Corporation Wi-Fi 6 AX210/AX211/AX411 160MHz [8086:2725] (rev 1a)
        Subsystem: Intel Corporation Wi-Fi 6 AX210 160MHz [8086:0024]
        Kernel modules: iwlwifi
                       (absence de "Kernel driver in use" = module non actif)

5. Test de confirmation

Triangle disparu, catégorie correcte (Cartes réseau, Contrôleurs audio…), fonction testée (son joué, réseau connecté). Limite : un pilote générique Microsoft peut fonctionner partiellement (pas de touches de fonction, pas de micro) → préférer celui du fabricant.

6. Correction

Pilote du fabricant / Windows Update facultatif ; Linux : firmware/pilote de la distribution. Ordre recommandé sur un poste neuf : chipset → stockage → réseau → graphique → audio → reste.

7. Validation

  • Gestionnaire de périphériques sans aucun triangle (Affichage → Afficher les périphériques cachés pour vérifier) ; test de chaque fonction ; Linux : « Kernel driver in use: iwlwifi ».

8. Réponse d'examen modèle

Réponse rédigée attendue

Après l'installation, le Gestionnaire de périphériques affiche un « Contrôleur réseau » sous « Autres périphériques », Code 28 : pilote absent. J'ouvre Propriétés → Détails → ID du matériel : PCI\VEN_8086&DEV_2725 = carte Wi-Fi Intel AX210. Le poste n'a pas d'accès réseau : je télécharge sur un autre PC le pilote Wi-Fi depuis la page support du modèle exact du portable, je le copie sur clé et l'installe. Validation : la carte apparaît dans « Cartes réseau » sans triangle, le Wi-Fi se connecte, puis je passe Windows Update (mises à jour facultatives) pour le reste des pilotes.

Perd des points : « installer un pilote trouvé sur Internet » sans source fiable ni identification ; confondre Code 28 (pilote absent) et Code 22 (désactivé).

9. Pièges et variantes

  • Code 22 « Ce périphérique est désactivé » / flèche vers le bas → simplement Activer (vérifier pourquoi il a été désactivé).
  • Le Wi-Fi « manque » mais la carte est saine : interrupteur/touche avion, mode avion — à vérifier avant tout pilote. Réseau ensuite : → Fiche 4 · Wi-Fi.

2. Causes possibles (classées)

  1. MAJ de pilote récente (Windows Update ou utilitaire) — pilote.
  2. Port/câble/hub USB, alimentation insuffisante du port — matériel/branchement.
  3. Périphérique défaillant — matériel.
  4. Pilote non signé — sécurité.

3. Questions initiales et sécurité

  • Depuis quand ? Une MAJ ? Marche-t-il sur un autre PC ? Point de restauration ?

4. Diagnostic pas à pas

  1. Onglet Pilote : date et version ; Événements (onglet) : « Périphérique installé/configuré » récent ?

    SI pilote changé juste avant la panne → Restaurer le pilote (bouton actif seulement si une version précédente existe).

    SINON → étape 2.

  2. Code 43 sur USB : autre port (direct, arrière), autre câble, autre PC.

    SI le périphérique fonctionne ailleurs → logiciel/port de ce PC : désinstaller le périphérique + pilote, redémarrer ; pilote du contrôleur USB/chipset.

    SINON (KO partout) → périphérique défaillant → Fiche 1.

  3. Carte graphique Code 43 : désinstaller le pilote proprement, installer la version du fabricant ; si persiste avec plusieurs versions → matériel (Fiche 1).

5. Test de confirmation

Le retour à l'ancienne version rétablit la fonction et la nouvelle la recasse → pilote confirmé. Le test croisé sur un autre PC sépare matériel et logiciel. Limite : un défaut intermittent du câble peut tromper un test court.

6. Correction

Restaurer le pilote → bloquer temporairement la MAJ fautive (outil « Afficher ou masquer les mises à jour » de Microsoft, ou suspendre les MAJ) → signaler au fabricant. Sinon désinstaller (cocher « Tenter de supprimer le pilote de ce périphérique ») et réinstaller la version stable.

7. Validation

  • État « Ce périphérique fonctionne correctement » ; fonction testée après redémarrage ; journal Système sans erreur du pilote.

8. Réponse d'examen modèle

Réponse rédigée attendue

L'imprimante USB affiche Code 43 depuis hier. Le Code 43 dit que le périphérique ou son pilote a signalé une défaillance : il ne désigne pas lequel. Test croisé : sur un autre PC, l'imprimante fonctionne ; sur ce PC, avec un autre câble et un port arrière, Code 43 persiste. L'onglet Pilote montre une version installée hier par Windows Update : je clique sur Restaurer le pilote. L'imprimante fonctionne. Conclusion : pilote récent incompatible. Je suspends les mises à jour de ce pilote et note la version fautive dans le rapport.

9. Pièges et variantes

  • Code 43 + hub non alimenté avec un disque 2,5" → alimentation du port, pas pilote.
  • Désactiver la « Gestion de l'alimentation » USB (onglet Gestion de l'alimentation : « Autoriser l'ordinateur à éteindre ce périphérique ») pour un périphérique qui « disparaît » après veille.

P3.3 — Écran bleu (écran d'arrêt / BSOD) : lire, relever, tester, corriger

Fréquence : fréquent · Gravité : élevée (perte de travail, risque pour les données si disque)

1. Symptômes observables

  • « Votre PC a rencontré un problème et doit redémarrer… », code d'arrêt en texte (DRIVER_IRQL_NOT_LESS_OR_EQUAL), parfois « Ce qui a échoué : nvlddmkm.sys » ; QR code. Sur les Windows 11 les plus récents, l'écran d'arrêt est noir et plus sobre : même lecture.
  • Redémarrage immédiat (redémarrage automatique) : l'utilisateur dit « le PC redémarre tout seul ».

2. Causes possibles (classées)

  1. Pilote récent ou défectueux (graphique, réseau, antivirus, VPN) — pilote.
  2. Mise à jour Windows — OS.
  3. RAM instable (XMP, barrette) — matériel.
  4. Disque/système de fichiers — stockage.
  5. Surchauffe, alimentation, surcadençage — matériel.

3. Questions initiales et sécurité

  • Quand (démarrage, jeu, veille, copie), depuis quand, quel changement ? Fréquence ? Sauvegarde si le disque est suspect.

4. Diagnostic pas à pas

  1. Récupérer le code : Observateur d'événements → Journaux Windows → Système → filtre ID 1001 (source BugCheck / Windows Error Reporting) : « L'ordinateur a redémarré après une vérification d'erreur. La vérification d'erreur était : 0x000000d1 (…) Un vidage a été enregistré dans : C:\Windows\Minidump\102726-12345-01.dmp ». Ou Moniteur de fiabilité (perfmon /rel) : « Arrêt Windows inattendu ». Pour lire l'écran : décocher « Redémarrer automatiquement » (sysdm.cpl → Paramètres système avancés → Démarrage et récupération → Paramètres).

    SI un fichier .sys est cité → identifier son pilote (nom du fichier, propriétés dans C:\Windows\System32\drivers) → étape 3.

    SINON → étape 2 (classer le code).

  2. Classer le code (tableau ci-dessous) et croiser avec le contexte.
  3. Test logiciel : mode sans échec (P6.1) ou démarrage sélectif (msconfig).

    SI plus d'écran bleu en mode sans échec et sous la même charge → pilote/service tiers : restaurer/désinstaller le pilote récent (P3.2), désinstaller la MAJ (P3.5).

    SINON → étape 4.

  4. Test matériel : Diagnostic de mémoire Windows (mdsched.exe) / MemTest86, XMP désactivé (→ Fiche 1 · RAM) ; SMART et chkdsk C: ; températures (→ Fiche 1 · Surchauffe).
  5. Fichiers système : DISM puis sfc /scannow (P6.3).

5. Test de confirmation

Reproduire la condition (même jeu, même veille, même copie) après correction, sur une durée comparable à la fréquence initiale (un BSOD hebdomadaire ne se valide pas en 10 minutes). Limite : un code « pilote » peut être provoqué par une RAM défaillante qui corrompt le pilote ; codes variés à chaque plantage = plutôt matériel (RAM/alimentation).

6. Correction

Selon cause confirmée : restaurer/mettre à jour le pilote cité (version fabricant), désinstaller la MAJ, désactiver XMP/remplacer la barrette, réparer le système de fichiers, DISM/SFC, nettoyer/refroidir. Désinstaller l'antivirus tiers si cité (Microsoft Defender reprend la protection).

7. Validation

  • Aucun nouvel événement 1001/41 sur la période ; Moniteur de fiabilité stable ; condition déclenchante reproduite sans plantage ; réactiver le redémarrage automatique.

8. Réponse d'examen modèle

Réponse rédigée attendue

Observation : écran bleu VIDEO_TDR_FAILURE, « Ce qui a échoué : nvlddmkm.sys », uniquement en jeu, depuis la mise à jour du pilote NVIDIA du 20/10 (journal Système, BugCheck 1001 répétés). Hypothèses : 1) pilote graphique récent ; 2) surchauffe de la carte graphique ; 3) alimentation. Test 1 : Gestionnaire de périphériques → Cartes graphiques → Pilote → Restaurer le pilote (version précédente) ; je rejoue 1 h au même jeu : aucun plantage. Test 2 (contrôle) : températures relevées normales. Conclusion : pilote graphique récent. Correction : version précédente conservée, MAJ automatique de ce pilote suspendue. Validation : une semaine sans événement 1001, utilisateur informé.

Perd des points : « la carte graphique est HS » sur un seul écran bleu ; réinstaller Windows ; ne pas relever le code ; ignorer le fichier .sys cité.

9. Pièges et variantes

  • Kernel-Power 41 dans le journal = conséquence (arrêt non propre), jamais la cause.
  • Pas de minidump : fichier d'échange désactivé/trop petit, disque plein, ou coupure d'alimentation (pas un BSOD).
  • Écran bleu seulement à la sortie de veille → DRIVER_POWER_STATE_FAILURE, pilote réseau/graphique, mise à jour du BIOS.
  • Plusieurs causes concomitantes (pilote + RAM) : corriger, valider, puis corriger la suivante — un changement à la fois.

P3.4 — Linux : kernel panic, gel, plantage après mise à jour du noyau

Fréquence : rare à moyen · Gravité : élevée

1. Symptômes observables

  • Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0) (initramfs manquant) ; Kernel panic - not syncing: Attempted to kill init! ; gel complet (clavier inactif, Verr Num ne s'allume plus).

2. Causes possibles (classées)

  1. MAJ du noyau interrompue → initramfs absent — OS/paquets.
  2. Nouveau noyau incompatible avec un pilote (DKMS NVIDIA, VirtualBox) — pilote.
  3. RAM, surchauffe — matériel.

3. Questions initiales et sécurité

  • Coupure pendant une mise à jour ? Depuis quand ? Ne jamais supprimer le noyau qui fonctionne.

4. Diagnostic pas à pas

  1. GRUB (Maj en BIOS, Échap en UEFI) → Advanced options for Ubuntu → noyau précédent.

    SI l'ancien noyau démarre → noyau récent en cause : étape 2.

    SINON → aucun noyau : live + chroot (P1.5) ; si gel aussi en live → matériel (Fiche 1).

  2. Sur l'ancien noyau : ls /boot (initrd.img du nouveau noyau présent ?), sudo dpkg --configure -a, journalctl -b -1 -p err (si le journal est persistant).

    SI initrd manquant → sudo update-initramfs -u -k all, sudo update-grub.

    SINON → module tiers (DKMS) : dkms status, réinstaller le pilote.

5. Test de confirmation

Le nouveau noyau démarre après régénération (uname -r = version la plus récente).

6. Correction

Régénérer initramfs ; terminer la configuration des paquets ; à défaut, garder le précédent par défaut et attendre le correctif.

7. Validation

  • Deux démarrages sur le nouveau noyau ; journalctl -b -p err sans erreur critique ; sudo apt update && sudo apt upgrade sans erreur.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le message « Unable to mount root fs on unknown-block(0,0) » après une mise à jour coupée indique que le noyau démarre sans son image initramfs. Je démarre sur le noyau précédent par « Advanced options » : le système fonctionne, ce qui confirme que seul le nouveau noyau est incomplet. Je termine la configuration (sudo dpkg --configure -a), régénère l'initramfs (sudo update-initramfs -u -k all) et le menu (sudo update-grub). Validation : démarrage sur le nouveau noyau, uname -r le confirme.

9. Pièges et variantes

  • /boot plein (partition séparée) bloque l'installation des noyaux : df -h /boot, sudo apt autoremove (lire la liste, conserver le noyau en cours).

P3.5 — Windows Update échoue, ou « Annulation des modifications apportées à votre ordinateur »

Fréquence : très fréquent · Gravité : moyenne (sécurité), élevée si boucle

1. Symptômes observables

  • Paramètres → Windows Update : « Échec de l'installation » + code ; Historique des mises à jour (Windows 11 : Windows Update → Historique des mises à jour ; Windows 10 : Mise à jour et sécurité → Windows Update → Afficher l'historique des mises à jour).
  • Au redémarrage : « Nous n'avons pas pu terminer les mises à jour. Annulation des modifications. Ne mettez pas votre ordinateur hors tension. » ; journal Système WindowsUpdateClient ID 20.

2. Causes possibles (classées)

  1. Espace disque — stockage.
  2. Connexion/VPN/proxy/heure fausse — réseau/configuration.
  3. Magasin de composants abîmé — OS.
  4. Pilote/logiciel incompatible avec une mise à jour de fonctionnalité — compatibilité.

3. Questions initiales et sécurité

  • Une seule MAJ ou toutes ? Un seul PC ? Ne pas couper l'alimentation pendant « Annulation des modifications ».

4. Diagnostic pas à pas

  1. Lire le code et la KB dans l'historique. Appliquer la ligne du tableau.
  2. Paramètres → Système → Résolution des problèmes → Autres utilitaires → Windows Update (Windows 10 : Mise à jour et sécurité → Résolution des problèmes → Utilitaires supplémentaires).
  3. Admin : DISM /Online /Cleanup-Image /RestoreHealth puis sfc /scannow, redémarrer, réessayer.

    SI échec persistant sur une seule KB → la télécharger depuis le catalogue Microsoft Update et l'installer manuellement.

    SINON (mise à jour de fonctionnalité) → Assistant d'installation de Windows 11 / réparation sur place avec l'ISO (setup.exe, « Conserver les fichiers et applications »).

  4. Si une MAJ installée cause une panne : Windows Update → Historique → Désinstaller des mises à jour ; si Windows ne démarre pas : WinRE → Désinstaller des mises à jour.

5. Test de confirmation

La MAJ apparaît « Installée avec succès » dans l'historique après la correction de la cause supposée.

6. Correction

Selon code. Réinitialiser les composants (arrêt de wuauserv et bits, renommage de C:\Windows\SoftwareDistribution en .old, redémarrage des services) est une marche avancée : elle efface l'historique local des MAJ mais pas les MAJ installées.

7. Validation

  • « Vous êtes à jour » ; winver (build attendue) ; pas d'événement 20 ; programmes métier testés.

8. Réponse d'examen modèle

Réponse rédigée attendue

L'historique indique l'échec de la KB mensuelle avec le code 0x80070070, soit un espace disque insuffisant ; Paramètres → Stockage confirme 1,2 Go libres sur C:. Je libère de l'espace sans toucher aux documents (fichiers temporaires, nettoyage des fichiers système, téléchargements avec accord), j'atteins 25 Go libres et relance Windows Update : installation réussie. Je n'ai pas désactivé les mises à jour, qui protègent le poste.

9. Pièges et variantes

  • Désactiver Windows Update pour « régler » le problème : faute de sécurité.
  • MAJ en boucle sur plusieurs PC le même jour : MAJ défectueuse publiée → la masquer, attendre le correctif.

P3.6 — Linux : apt/dpkg en erreur (verrou, installation interrompue, dépendances)

Fréquence : fréquent · Gravité : moyenne

1. Symptômes observables

E: Could not get lock /var/lib/dpkg/lock-frontend. It is held by process 2154 (unattended-upgr)
E: dpkg was interrupted, you must manually run 'sudo dpkg --configure -a' to correct the problem.
The following packages have unmet dependencies: ... E: Unmet dependencies. Try 'apt --fix-broken install'
E: Unable to locate package libreofice
W: Failed to fetch http://... Temporary failure resolving 'archive.ubuntu.com'

2. Causes possibles (classées)

  1. Une autre installation en cours (mises à jour automatiques, Logithèque) — normal.
  2. Coupure pendant une MAJ — interruption.
  3. Dépôt tiers ou paquet .deb incompatible — dépendances.
  4. Faute de frappe / liste non mise à jour — utilisateur.
  5. DNS/réseau — Fiche 4.

3. Questions initiales et sécurité

  • Ne jamais supprimer les fichiers de verrou pendant qu'un processus apt/dpkg tourne (risque de base dpkg incohérente).

4. Diagnostic pas à pas

  1. Verrou : ps aux | grep -E 'apt|dpkg'.

    SI un processus tourne (unattended-upgr) → attendre la fin.

    SINON (processus absent, coupure) → sudo dpkg --configure -a.

  2. Dépendances : sudo apt --fix-broken install ; lire ce qui sera supprimé avant de répondre O.
  3. Unable to locate : sudo apt update puis apt search libreoffice (nom exact).
  4. Échec de téléchargement : ping -c 3 archive.ubuntu.com ; DNS → Fiche 4.

5. Test de confirmation

sudo apt update && sudo apt upgrade se termine sans « E: ».

6. Correction

Voir étapes ; retirer le dépôt tiers fautif (/etc/apt/sources.list.d/, copie avant) ; historique : /var/log/apt/history.log.

7. Validation

  • Logiciel installé et lancé ; dpkg -l | grep -v '^ii' ne montre plus de paquet à moitié configuré (iU, iF).

8. Réponse d'examen modèle

Réponse rédigée attendue

Le message « dpkg was interrupted » fait suite à la coupure de courant pendant la mise à jour : des paquets sont restés non configurés. Je vérifie qu'aucun processus apt/dpkg ne tourne (ps aux | grep -E 'apt|dpkg'), puis je lance sudo dpkg --configure -a, puis sudo apt --fix-broken install en lisant la liste proposée. Validation : sudo apt update && sudo apt upgrade sans erreur, aucun paquet en état anormal dans dpkg -l.

Perd des points : sudo rm /var/lib/dpkg/lock* sans vérifier les processus ; forcer avec dpkg --force-all.

9. Pièges et variantes

  • Fedora : sudo dnf install, dnf history, dnf history undo N.
