3.A Procédures — Le PC ne démarre pas le système

Prérequis commun : le POST passe (logo du fabricant, accès au setup firmware). Sinon → Fiche 1 · POST. Disque absent du setup firmware : → Fiche 1 · Stockage non détecté.

P1.1 — « Reboot and Select proper Boot device », « No bootable device », « Operating system not found »

Fréquence : très fréquent · Gravité : bloquante, données en général intactes

1. Symptômes observables

  • Texte blanc sur fond noir, juste après le logo, émis par le firmware (aucun logo Windows, aucun menu GRUB).
  • Variantes : « Reboot and Select proper Boot device or Insert Boot Media in selected Boot device and press a key », « No bootable device -- insert boot disk and press any key », « Boot Device Not Found », « No boot device available », PXE qui tente le réseau (« PXE-E61 », « Checking media presence… »).
  • Contexte typique : après un reset CMOS / pile changée, une mise à jour du BIOS, un ajout de disque, une clé USB oubliée, un clonage, une installation de Linux, une suppression de partition « inutile ».

2. Causes possibles (classées)

  1. Support non démarrable placé en tête : clé USB, disque de données, carte réseau (PXE) — configuration.
  2. Mode de démarrage modifié : système installé en UEFI (disque GPT + ESP) mais firmware passé en CSM/Legacy, ou l'inverse — configuration firmware (souvent après reset CMOS ou MAJ BIOS).
  3. Entrée NVRAM « Windows Boot Manager » / « ubuntu » perdue (reset, MAJ BIOS) alors que l'ESP est intacte — configuration.
  4. ESP supprimée/formatée, ou chargeur absent (\EFI\Microsoft\Boot\bootmgfw.efi, \EFI\BOOT\BOOTX64.EFI) — OS/partitions.
  5. Disque non détecté, câble, M.2 mal inséré, disque défaillant — matériel → Fiche 1.

3. Questions initiales et sécurité

  • Qu'a-t-on fait juste avant ? (pile, BIOS, disque ajouté, autre système installé, « nettoyage » de partitions)
  • Y a-t-il une clé USB, un DVD, un disque externe branché ?
  • BitLocker/chiffrement de l'appareil actif ? (un changement de mode ou de Secure Boot déclenchera la demande de clé : la récupérer AVANT, P1.7).
  • Aucun geste sur le disque à ce stade : on ne touche qu'aux réglages firmware, réversibles. Noter chaque réglage d'origine avant de le changer.

4. Diagnostic pas à pas

  1. Débrancher tout support amovible (USB, carte SD, DVD) et redémarrer. — attendu : le système démarre.

    SI le système démarre → cause = support amovible en tête ; corriger l'ordre (étape 3).

    SINON → étape 2.

  2. Entrer dans le setup firmware (Suppr/F2 selon le fabricant ; ou, si Windows démarrait encore, Paramètres → Système → Récupération → Démarrage avancé → Dépannage → Options avancées → Paramètres du microprogramme UEFI). Onglet stockage/informations : le disque système est-il listé avec sa bonne taille ?

    SI non listé → panne de détection, pas de l'OS : → Fiche 1 · Stockage non détecté.

    SINON → étape 3.

  3. Onglet Boot : lire l'ordre et le mode. — attendu en UEFI : « Windows Boot Manager (nom du disque) » ou « ubuntu » en premier ; CSM désactivé (ou « UEFI only »).

    SI l'entrée existe mais n'est pas en tête → la remonter, F10 (enregistrer), redémarrer.

    SINON SI seule une entrée brute du disque apparaît (« SATA : Samsung SSD… ») et le CSM/Legacy est activé → le firmware a probablement été remis en mode hérité : repasser en UEFI (Boot Mode = UEFI, CSM = Disabled), redémarrer. SINON (aucune entrée Windows en UEFI) → étape 4.

  4. Utiliser le menu de démarrage ponctuel (F12, F11, F8, Échap ou F9 selon le fabricant) et choisir l'entrée du disque. — permet de tester sans modifier l'ordre.

    SI le système démarre ainsi → l'ESP est saine, seule l'entrée NVRAM/ordre manque : la recréer (P1.2, bcdboot la réinscrit) ou la placer en tête.

    SINON → démarrer sur une clé d'installation Windows (ou live Linux) pour inspecter les partitions en lecture (étape 5).

  5. Depuis WinRE (clé Windows → Réparer l'ordinateur → Dépannage → Invite de commandes) : diskpart puis list disk, list vol (lecture seule). Dans list disk, une * dans la colonne GPT = disque GPT.

    SI disque GPT avec un volume FAT32 de 100–300 Mo (ESP) et le volume NTFS Windows → chargeur/BCD à recréer : P1.2.

    SINON SI disque MBR → le système est en mode hérité : remettre CSM/Legacy dans le firmware (ou convertir plus tard, P2.2). SINON (aucune ESP sur GPT) → ESP supprimée : la recréer exige de modifier les partitions → Fiche 1 · Partitionnement + bcdboot, sauvegarde préalable.

5. Test de confirmation

La cause est confirmée quand le seul réglage modifié (ordre, mode, entrée recréée) rend le démarrage possible et que le remettre dans l'état fautif reproduit le message. Limite : un démarrage réussi ne prouve pas que le disque est sain (lire SMART si le contexte est suspect, Fiche 1).

6. Correction

  1. Retirer le support amovible ; ordre : entrée du système en premier ; enregistrer (F10).
  2. Remettre le mode d'origine (UEFI pour un disque GPT, hérité pour un disque MBR). Ne pas « essayer » de convertir un disque pour s'adapter au firmware.
  3. Si l'entrée NVRAM manque mais l'ESP est intacte : bcdboot C:\Windows (depuis Windows) ou depuis WinRE avec les lettres vérifiées (P1.2).
  4. Après MAJ du BIOS : revérifier Secure Boot, TPM, mode SATA (AHCI/RST), tous remis aux valeurs par défaut.

7. Validation

  • Deux démarrages à froid (arrêt complet) sans menu ponctuel ; entrée correcte en tête ; date/heure firmware correctes (pile) ; Windows : msinfo32 → « Mode BIOS : UEFI » cohérent avec le disque GPT.
  • Noter dans le rapport le réglage d'origine et le réglage final.

8. Réponse d'examen modèle

Réponse rédigée attendue

Observation : message « Reboot and Select proper Boot device » affiché par le firmware après le changement de la pile ; aucun logo Windows. Hypothèses (de la plus probable à la moins probable) : 1) remise à zéro des réglages firmware → mode CSM/Legacy réactivé alors que Windows est installé en UEFI sur disque GPT ; 2) ordre de démarrage modifié ; 3) disque non détecté. Tests : j'entre dans le setup, je vérifie que le SSD est détecté avec sa capacité (sinon piste matérielle) ; je lis le mode de démarrage et l'ordre. Je constate CSM activé et aucune entrée « Windows Boot Manager ». Correction : je repasse en UEFI (CSM désactivé), je place « Windows Boot Manager » en premier, j'enregistre, je règle la date et l'heure. Validation : deux démarrages à froid réussis, msinfo32 indique « Mode BIOS : UEFI ». Aucune action sur le disque n'a été nécessaire ; je note les réglages dans le rapport.

Perd des points : proposer « réinstaller Windows » ou « bootrec /fixmbr » d'emblée ; conclure « disque HS » sans avoir regardé s'il est détecté ; oublier BitLocker avant de changer le mode/Secure Boot.

9. Pièges et variantes

Piège Le message est identique pour un disque mort et pour un mauvais ordre : seule la détection dans le setup sépare matériel et configuration.
Piège Après une MAJ Windows dans un double démarrage, « Windows Boot Manager » repasse en tête : ce n'est pas une panne de GRUB (P1.5).
  • Variante intermittente : démarre parfois → disque qui met du temps à répondre, câble, alimentation (Fiche 1) ou pile faible (heure fausse à chaque démarrage).
  • Variante PXE : « PXE-E61: Media test failure, check cable » = le firmware essaie le réseau faute de disque démarrable ; ce n'est pas un problème réseau.

P1.2 — Windows Boot Manager : « Votre PC/appareil doit être réparé » (0xc000000f, 0xc0000034, 0xc000000e) — reconstruire le démarrage

Fréquence : fréquent · Gravité : bloquante, données intactes si l'on reste prudent

1. Symptômes observables

  • Écran de récupération : « Votre PC/appareil doit être réparé. Le fichier de données de configuration de démarrage ne contient pas d'informations valides pour un système d'exploitation. Fichier : \EFI\Microsoft\Boot\BCD Code d'erreur : 0xc000000f » (ou \Boot\BCD en mode hérité).
  • 0xc0000034 : BCD sans entrée valide ; 0xc000000e / 0xc0000225 : « Un périphérique requis n'est pas connecté ou n'est pas accessible » avec \Windows\system32\winload.efi → la partition Windows désignée par le BCD est introuvable.
  • Mode hérité : « BOOTMGR is missing — Press Ctrl+Alt+Del to restart ».

2. Causes possibles (classées)

  1. Arrêt brutal pendant une MAJ, BCD abîmé — OS.
  2. Manipulation de partitions (outil tiers, installation Linux, clonage vers un nouveau disque) — partitions/OS.
  3. Disque système déplacé, autre disque en tête, mode SATA changé — configuration.
  4. Secteurs défectueux sur l'ESP ou le disque — matériel (Fiche 1).

3. Questions initiales et sécurité

  • Clé d'installation Windows de la même architecture (x64) disponible ? (sinon F11/« Options de démarrage avancées » si l'écran le propose).
  • BitLocker : dans WinRE, le volume chiffré est verrouillé ; il faut la clé de récupération pour manage-bde -unlock avant toute commande.
  • Sauvegarde : si les données sont précieuses et sans copie, les copier d'abord (WinRE → notepad → Fichier → Ouvrir sert d'explorateur, ou clé live Linux).

4. Diagnostic pas à pas

  1. Démarrer sur WinRE : clé d'installation → langue → Suivant → Réparer l'ordinateur → Dépannage → Options avancées → Outil de redémarrage système (Réparation du démarrage). — attendu : « La réparation du démarrage » corrige le BCD.

    SI Windows démarre ensuite → valider (section 7).

    SINON (« La réparation du démarrage n'a pas pu réparer votre PC ») → noter le chemin du journal SrtTrail.txt, étape 2.

  2. Invite de commandes : lire le BCD bcdedit /enum all. — attendu : une entrée « Gestionnaire de démarrage Windows » et une entrée « Chargeur de démarrage Windows » avec device partition=C:.

    SI « Le magasin de données de configuration de démarrage n'a pas pu être ouvert » → BCD absent/illisible : étape 3.

    SINON SI device/osdevice = unknown → la partition cible a changé : étape 3. SINON BCD cohérent → chercher ailleurs (fichiers système, P1.3).

  3. Identifier les volumes : diskpart → list vol → exit. Repérer : volume NTFS avec Windows (souvent D: ou C: dans WinRE, vérifier avec dir D:\Windows) ; volume FAT32 de ~100–300 Mo, étiquette « Système » ou info « Caché » = ESP (sans lettre).

    SI l'ESP existe → étape 4.

    SINON (disque GPT sans FAT32) → l'ESP a été supprimée : la recréer touche aux partitions, sauvegarde obligatoire, → Fiche 1 · Partitionnement, puis étape 4.

  4. Recréer les fichiers de démarrage UEFI avec bcdboot (voir commandes ci-dessous). — attendu : message de succès de bcdboot.

    SI « Échec lors de la tentative de copie des fichiers de démarrage » → mauvaise lettre de l'ESP ou ESP pleine/abîmée : revérifier list vol, chkdsk S:.

    SINON redémarrer sans la clé.

X:\Sources> diskpart
DISKPART> list vol
DISKPART> select vol 3          (le volume FAT32 de 100 Mo, vérifié)
DISKPART> assign letter=S
DISKPART> exit
X:\Sources> dir D:\Windows      (confirme que D: est bien Windows)
X:\Sources> bcdboot D:\Windows /s S: /f UEFI
  N° volume   Ltr  Nom          Fs     Type        Taille   Statut     Info
  ----------  ---  -----------  -----  ----------  -------  ---------  --------
  Volume 0     E   CCCOMA_X64F  UDF    DVD-ROM     5 Go     Sain
  Volume 1     D                NTFS   Partition   475 G    Sain
  Volume 2                      NTFS   Partition   750 M    Sain       Masqué
  Volume 3                      FAT32  Partition   100 M    Sain       Masqué

Attention Dans diskpart, seules list, select, detail et assign sont utiles ici. clean, delete partition, format, convert effacent : interdits pour réparer un démarrage. Prérequis avant bcdboot : volume Windows identifié par dir, données sauvegardées si possible, réparation automatique déjà tentée. Alternative prudente : Réparation du démarrage (automatique) ou restauration du système.

Mode hérité (disque MBR uniquement) : bootrec /fixmbr (réécrit le code d'amorçage du MBR sans toucher aux partitions), bootrec /fixboot (secteur de démarrage de la partition système), bootrec /scanos (liste les Windows trouvés), bootrec /rebuildbcd (propose d'ajouter les Windows trouvés au BCD). Si /rebuildbcd annonce « Nombre total d'installations Windows identifiées : 0 » alors que Windows est présent : bcdedit /export C:\bcdbackup, attrib C:\boot\bcd -h -r -s, ren C:\boot\bcd bcd.old, puis bootrec /rebuildbcd.

Piège bootrec est un outil du démarrage hérité. Sur un PC UEFI/GPT : /fixmbr est sans effet utile (le MBR protecteur ne sert pas au démarrage), /fixboot renvoie souvent « Accès refusé » sur Windows 10/11 récents. L'outil adapté en UEFI est bcdboot.

5. Test de confirmation

bcdedit /enum depuis Windows redémarré montre device partition=C: et path \Windows\system32\winload.efi. Limite : si le BCD était abîmé par des secteurs défectueux, la panne reviendra → lire SMART et le journal Système (disk 7).

6. Correction

  1. Réparation automatique (WinRE) ;
  2. sinon bcdboot en UEFI / bootrec en hérité, avec lettres vérifiées ;
  3. si un 2e disque/clone est en cause : retirer l'ancien disque ou remettre le bon en tête ;
  4. retirer la lettre S: n'est pas nécessaire (elle disparaît au redémarrage).

7. Validation

  • Démarrage sans clé, 2 fois ; bcdedit /enum cohérent ; msinfo32 Mode BIOS UEFI ; dans un double démarrage, vérifier que GRUB est toujours proposé (bcdboot peut remettre Windows en tête : P1.5).
  • Si BitLocker : manage-bde -status → Protection activée.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le code 0xc000000f sur \EFI\Microsoft\Boot\BCD indique que Windows Boot Manager démarre mais que son magasin de configuration (BCD) est absent ou invalide : le firmware et le disque fonctionnent (le chargeur est lu). 1) Je démarre sur une clé d'installation Windows, « Réparer l'ordinateur », et je lance la réparation du démarrage. 2) En cas d'échec, dans l'invite de commandes, je lis bcdedit /enum all, puis j'identifie les volumes avec diskpart / list vol (lecture seule) : Windows en D: (vérifié par dir D:\Windows), ESP FAT32 de 100 Mo sans lettre. 3) Je lui attribue la lettre S: et je recrée les fichiers de démarrage : bcdboot D:\Windows /s S: /f UEFI. Je n'utilise ni clean ni format, et je n'utilise pas bootrec /fixmbr, inadapté en UEFI. 4) Validation : deux démarrages normaux, bcdedit cohérent, données présentes ; rapport.

Perd des points : confondre ce message (chargeur Windows) avec « No bootable device » (firmware) ; lancer bcdboot C:\Windows dans WinRE sans vérifier la lettre ; recommander une réinstallation.

9. Pièges et variantes

  • Après clonage HDD → SSD : 0xc000000e car le BCD pointe vers l'ancien disque ; débrancher l'ancien ou bcdboot depuis le nouveau.
  • Deux ESP (deux disques) : le firmware démarre l'ESP de l'ancien disque → ordre de démarrage.
  • « BOOTMGR is missing » avec une clé USB de données en tête → retirer la clé avant tout.
  • Panne concomitante : BCD abîmé + disque qui faiblit (disk 7/153 dans les journaux) → sauvegarde d'abord, remplacement (Fiche 1), puis réparation.

P1.3 — « Préparation de la réparation automatique » en boucle / « Votre PC n'a pas démarré correctement »

Fréquence : fréquent · Gravité : bloquante, souvent réversible

1. Symptômes observables

  • Logo puis « Préparation de la réparation automatique », « Diagnostic de votre PC », puis « La réparation automatique n'a pas pu réparer votre PC » / « Votre PC n'a pas démarré correctement » avec boutons Redémarrer et Options avancées.
  • Boucle : redémarre, échoue, recommence. Journal de la réparation : C:\Windows\System32\Logfiles\Srt\SrtTrail.txt.

2. Causes possibles (classées)

  1. Mise à jour Windows ou pilote récent qui empêche le démarrage — OS/pilote.
  2. Logiciel installé au démarrage (antivirus tiers, utilitaire disque) — application.
  3. Fichiers système abîmés (coupure de courant) — OS.
  4. Système de fichiers abîmé — stockage logique.
  5. Disque qui faiblit, RAM instable — matériel (Fiche 1).

3. Questions initiales et sécurité

  • Quand ? après MAJ, coupure, installation ? un seul PC ou plusieurs (MAJ commune) ?
  • Ne pas cliquer sur « Réinitialiser ce PC » (dans Dépannage) : c'est la marche 5.
  • BitLocker : la clé sera demandée pour certaines options (invite de commandes, restauration).

4. Diagnostic pas à pas

  1. Options avancées → Invite de commandes → type C:\Windows\System32\Logfiles\Srt\SrtTrail.txt (lettre à vérifier par dir). — attendu : une ligne « Cause première trouvée » (ex. « Un pilote incorrect a été trouvé », « Les fichiers système sont corrompus », « Disque de démarrage introuvable »).

    SI un fichier .sys est cité → pilote : étape 2.

    SINON → étape 2 quand même (test discriminant).

  2. Options avancées → Paramètres → Redémarrer → touche 4 (mode sans échec) ou 5 (avec réseau).

    SI le mode sans échec démarre → cause = pilote/service/logiciel tiers : désinstaller le dernier pilote/logiciel/MAJ depuis ce mode (P6.1).

    SINON → étape 3.

  3. Options avancées → Désinstaller des mises à jour → « Désinstaller la dernière mise à jour qualité » (puis, si la panne suit une mise à jour majeure, « … de fonctionnalité »).

    SI démarre → cause = MAJ ; suspendre les MAJ le temps du correctif.

    SINON → étape 4.

  4. Options avancées → Restauration du système → point antérieur à la panne (P6.2).

    SI aucun point / échec → étape 5.

    SINON valider.

  5. Invite de commandes : vérifications du stockage puis fichiers système hors ligne : chkdsk D: (lecture), si erreurs chkdsk D: /f ; puis sfc /scannow /offbootdir=D:\ /offwindir=D:\Windows.

    SI chkdsk signale des secteurs défectueux / le disque est lent ou bruyant → sauvegarde des données d'abord, SMART (Fiche 1).

    SINON → si toujours en boucle : sauvegarde depuis WinRE/live, puis P6.4 avec accord.

5. Test de confirmation

La marche qui fait disparaître la boucle désigne la cause (pilote retiré, MAJ désinstallée, point restauré). Limite : la restauration du système retire plusieurs changements à la fois ; elle ne dit pas lequel était fautif.

6. Correction

Celle de la marche qui a réussi ; puis bloquer temporairement la réapparition (suspendre les MAJ 1 semaine, pilote du fabricant en version stable).

7. Validation

  • Trois démarrages normaux, Moniteur de fiabilité (perfmon /rel) sans nouvel événement critique, programmes métier testés.

8. Réponse d'examen modèle

Réponse rédigée attendue

La boucle de réparation automatique indique que Windows échoue après le chargeur (le BCD et le disque sont lus). Je procède du moins au plus invasif : 1) lecture de SrtTrail.txt pour la cause annoncée ; 2) démarrage en mode sans échec (Options avancées → Paramètres → 4) : s'il réussit, la cause est un élément tiers chargé au démarrage normal (pilote, service, logiciel), que je désinstalle ou restaure ; 3) sinon, désinstallation de la dernière mise à jour qualité ; 4) restauration du système au dernier point avant la panne ; 5) chkdsk puis SFC hors ligne avec la lettre vérifiée. La réinitialisation ne viendrait qu'après sauvegarde vérifiée et accord écrit. Validation : trois démarrages normaux et journaux propres.

Perd des points : « Réinitialiser ce PC » en premier ; SFC « en ligne » (sfc /scannow simple) dans WinRE, qui vérifie WinRE et non le Windows du disque.

9. Pièges et variantes

  • Boucle juste après coupure + disque HDD ancien : penser disque avant fichiers système.
  • Le mode sans échec ne démarre pas non plus → pas un pilote tiers : MAJ, fichiers système, disque.
  • « Votre PC a rencontré un problème » (écran bleu) en boucle avant la réparation → lire le code d'arrêt (P3.3), désactiver le redémarrage automatique (Paramètres de démarrage → 9).

P1.4 — Écran bleu INACCESSIBLE_BOOT_DEVICE (0x7B) au démarrage

Fréquence : assez fréquent · Gravité : bloquante

1. Symptômes observables

  • Écran d'arrêt dès le logo, code INACCESSIBLE_BOOT_DEVICE ; souvent suivi de la réparation automatique.
  • Contexte : réglage SATA changé (AHCI ↔ RAID/Intel RST), VMD activé, MAJ du BIOS, clonage vers un NVMe, MAJ Windows, disque déplacé dans un autre PC.

2. Causes possibles (classées)

  1. Mode du contrôleur de stockage modifié (le pilote chargé au démarrage ne correspond plus) — configuration firmware.
  2. Mise à jour / pilote de stockage — OS.
  3. Système de fichiers abîmé — stockage logique.
  4. Disque défaillant, câble — matériel.

3. Questions initiales et sécurité

  • Quelqu'un a-t-il réinitialisé le BIOS / changé le mode SATA ? Le disque vient-il d'un autre PC ?
  • Noter le mode actuel avant de le changer.

4. Diagnostic pas à pas

  1. Setup firmware → configuration du stockage (SATA Mode / Storage Configuration / VMD).

    SI le mode a changé (ex. RAID/RST alors que Windows a été installé en AHCI) → remettre l'ancien mode, redémarrer.

    SINON → étape 2.

  2. WinRE → Désinstaller des mises à jour (dernière qualité), puis Restauration du système.

    SI démarre → MAJ/pilote.

    SINON → étape 3.

  3. Invite WinRE : chkdsk D: (lettre vérifiée) puis /f si erreurs ; SMART (Fiche 1).

    SI erreurs physiques → sauvegarde et remplacement (Fiche 1).

    SINON → réparation/réinstallation avec accord (P6.4).

5. Test de confirmation

Remettre le mode d'origine fait démarrer ; le remettre fautif reproduit l'écran. Limite : ne pas multiplier les allers-retours sur un disque en RAID réel (risque pour la grappe).

6. Correction

Remettre le mode d'origine. Si l'on doit passer en AHCI (ex. installation d'un SSD) : depuis Windows, bcdedit /set {current} safeboot minimal → redémarrer dans le setup → passer en AHCI → Windows démarre en mode sans échec et charge le pilote AHCI → bcdedit /deletevalue {current} safeboot → redémarrer normalement.

Attention Ne jamais changer le mode d'un contrôleur qui porte une grappe RAID avec données : la grappe peut devenir illisible. Prérequis : sauvegarde. Alternative prudente : laisser le mode d'origine.

7. Validation

  • Démarrage normal ×2 ; Gestionnaire de périphériques → Contrôleurs de stockage sans triangle ; plus d'événement BugCheck 1001.

8. Réponse d'examen modèle

Réponse rédigée attendue

Le code INACCESSIBLE_BOOT_DEVICE signifie que le noyau a démarré mais ne parvient plus à accéder au volume système. Le changement récent (réinitialisation du BIOS) fait suspecter le mode du contrôleur SATA passé de AHCI à RAID. Test : je lis ce réglage dans le setup ; il est sur RAID ; je le remets sur AHCI : Windows démarre. Conclusion : cause confirmée par l'inversion du seul réglage modifié. Validation : deux démarrages, aucun BugCheck dans le journal Système. Si le réglage était correct, je testerais ensuite la désinstallation de la dernière mise à jour, puis l'état du disque.

Perd des points : « disque HS » sans test ; réinstallation directe.

9. Pièges et variantes

  • Même code après clonage sur NVMe derrière Intel VMD : pilote RST absent → soit désactiver VMD (si aucun RAID), soit installer le pilote avant clonage.
  • Même code sur un PC virtuel déplacé : type de contrôleur virtuel changé (SATA ↔ SCSI/NVMe).
