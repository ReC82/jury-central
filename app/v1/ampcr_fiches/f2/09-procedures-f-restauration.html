P6.1 — Windows instable ou bloqué après un changement : le mode sans échec comme test discriminant

Fréquence : très fréquent · Gravité : variable

1. Symptômes observables

  • Écran noir après connexion, écran bleu au démarrage, gel au bureau, programme au démarrage qui bloque, après installation d'un pilote/logiciel/MAJ.

2. Causes possibles (classées)

  1. Pilote tiers (graphique, imprimante, antivirus, VPN) — pilote.
  2. Logiciel/service lancé au démarrage — application/service.
  3. MAJ Windows — OS.
  4. Fichiers système/disque/matériel (si le mode sans échec échoue aussi).

3. Questions initiales et sécurité

  • Quel changement, à quelle date ? BitLocker (clé pour WinRE) ? Point de restauration ?

4. Diagnostic pas à pas

  1. Démarrer en mode sans échec (4) ou avec réseau (5). — attendu : bureau en basse résolution, mention « Mode sans échec » aux coins.

    SI le problème disparaît → cause chargée seulement en démarrage normal (pilote/service/programme tiers) : étape 2.

    SINON → cause plus profonde : MAJ (P3.5), restauration (P6.2), fichiers système (P6.3), disque/RAM (Fiche 1).

  2. En mode sans échec : annuler le dernier changement : Gestionnaire de périphériques → Restaurer le pilote ; Paramètres → Applications → désinstaller le logiciel récent ; Windows Update → Historique → Désinstaller des mises à jour.

    SI démarrage normal OK ensuite → cause confirmée.

    SINON → démarrage sélectif msconfig (services non-Microsoft désactivés) puis réactivation par moitiés.

5. Test de confirmation

Démarrage normal stable après le retrait d'un seul élément ; sa réinstallation reproduirait la panne (non obligatoire, mais c'est la preuve). Limite : le mode sans échec utilise un pilote graphique de base, il masque aussi les problèmes de pilote graphique (c'est voulu).

6. Correction

Retrait/remplacement de l'élément fautif ; version stable du fabricant ; retirer le mode sans échec forcé (msconfig/bcdedit /deletevalue).

7. Validation

  • 3 démarrages normaux ; fonction concernée testée ; Moniteur de fiabilité propre.

8. Réponse d'examen modèle

Réponse rédigée attendue

Depuis l'installation d'un logiciel de VPN, le PC reste sur un écran noir après la connexion. J'accède à WinRE (deux démarrages interrompus) → Dépannage → Options avancées → Paramètres → Redémarrer → 4. En mode sans échec, le bureau s'affiche : la cause est un élément chargé au démarrage normal. Je désinstalle le VPN installé la veille et redémarre normalement : le bureau s'affiche. Conclusion : le pilote réseau virtuel du VPN bloquait le démarrage. Validation : trois démarrages normaux ; je propose la version du VPN compatible avec cette version de Windows.

9. Pièges et variantes

  • Mot de passe demandé en mode sans échec : celui du compte (pas le PIN, Windows Hello inactif) ; compte Microsoft → mot de passe du compte Microsoft.
  • Rester bloqué en mode sans échec après msconfig : décocher « Démarrage sécurisé ».

P6.2 — Restauration du système (point de restauration)

Fréquence : fréquent · Gravité : marche 4 (réversible si lancée depuis Windows)

1. Symptômes observables

  • Panne apparue à une date connue sans cause unique isolée ; plusieurs changements depuis (pilotes, logiciels, MAJ).

2. Causes possibles (classées)

  1. Changement système (pilote, registre, programme) postérieur à un point existant.

3. Questions initiales et sécurité

  • Un point de restauration n'est pas une sauvegarde : il ne contient pas les documents et ne protège pas contre une panne de disque. Il ne supprime pas non plus les documents créés depuis.
  • Protection activée ? (elle ne l'est pas toujours par défaut).

4. Diagnostic pas à pas

  1. rstrui (ou rechercher « Créer un point de restauration » → Protection du système → Restauration du système…) ; depuis WinRE : Options avancées → Restauration du système.

    SI aucun point → protection désactivée : passer à P6.3 ; activer la protection après réparation.

    SINON → étape 2.

  2. Choisir le dernier point ANTÉRIEUR à la panne (date, description) → Rechercher les programmes concernés : liste de ce qui sera supprimé (programmes/pilotes installés après) et de ce qui pourrait être restauré.
  3. Terminer : ne pas éteindre pendant la restauration (secteur branché pour un portable).

    SI « La restauration du système n'a pas abouti » (ex. 0x80070005, antivirus) → réessayer depuis le mode sans échec ou WinRE.

    SINON → valider.

5. Test de confirmation

La panne a disparu ; message « La restauration du système s'est terminée correctement ». Limite : on ne sait pas lequel des changements annulés était fautif (le noter, réinstaller un à un si nécessaire).

6. Correction

Réinstaller les programmes utiles retirés (liste notée), sauf le suspect. Créer un point manuel avant toute intervention future : Protection du système → Créer (« Avant pilote X, 27/10 »). Activation : sélectionner C: → Configurer → Activer la protection du système, 5–10 % d'espace.

7. Validation

  • Panne disparue, programmes métier présents, protection active, point manuel créé.

8. Réponse d'examen modèle

Réponse rédigée attendue

Points disponibles : 18/10 (MAJ automatique), 22/10 (« Installation pilote imprimante »), 25/10 (MAJ). La panne est apparue le 23/10 après l'installation du pilote. Je choisis le point du 22/10, le dernier avant la panne, et non le plus ancien. « Rechercher les programmes concernés » indique que le pilote d'imprimante et un lecteur PDF installé le 24/10 seront retirés. Je préviens l'utilisateur que ses documents ne sont pas touchés, je restaure, puis je réinstalle le lecteur PDF et la version du pilote d'imprimante compatible. Validation : panne disparue, impression testée.

Perd des points : présenter le point de restauration comme une sauvegarde des documents ; choisir le point le plus ancien « par sécurité ».

9. Pièges et variantes

  • Restauration depuis WinRE : non annulable (pas de point créé avant elle), contrairement à celle lancée depuis Windows.

P6.3 — Fichiers système endommagés : DISM puis SFC (en ligne et hors ligne)

Fréquence : fréquent · Gravité : marche 3, sans risque pour les documents

1. Symptômes observables

  • Menu Démarrer/Paramètres qui ne s'ouvrent pas, erreurs de DLL système, écrans bleus CRITICAL_PROCESS_DIED, échecs de MAJ 0x80073712, après coupure de courant.

2. Causes possibles (classées)

  1. Fichiers système/magasin de composants abîmés — OS.
  2. Système de fichiers/disque — stockage (vérifier si SFC trouve toujours de nouvelles erreurs).

3. Questions initiales et sécurité

  • Invite de commandes en administrateur (clic droit → Exécuter en tant qu'administrateur) ; connexion Internet pour DISM (sinon source locale).

4. Diagnostic pas à pas

  1. DISM /Online /Cleanup-Image /ScanHealth (analyse, plusieurs minutes) — /CheckHealth est un contrôle rapide de l'état déjà enregistré.

    SI « Le magasin de composants peut être réparé. » → étape 2.

    SINON (« Aucun endommagement du magasin des composants n'a été détecté. ») → étape 3 directement.

  2. DISM /Online /Cleanup-Image /RestoreHealth — attendu : « L'opération de restauration s'est terminée correctement. » Si 0x800f081f (« Les fichiers sources sont introuvables ») → source locale : ISO de la même version montée en E: : DISM /Online /Cleanup-Image /RestoreHealth /Source:WIM:E:\sources\install.wim:1 /LimitAccess (index de l'édition installée, vérifiable par DISM /Get-WimInfo /WimFile:E:\sources\install.wim ; ESD: si le fichier est install.esd).
  3. sfc /scannow → lire le message final (tableau ci-dessous). Redémarrer et relancer une fois si des réparations ont été faites.
  4. Windows ne démarre pas : depuis WinRE, sfc /scannow /offbootdir=D:\ /offwindir=D:\Windows (lettre vérifiée) ; DISM hors ligne : DISM /Image:D:\ /Cleanup-Image /RestoreHealth /Source:WIM:E:\sources\install.wim:1.

Second sfc /scannow : « aucune violation d'intégrité » ; la fonction cassée remarche. Limite : si de nouvelles corruptions apparaissent à chaque passage → disque/RAM (Fiche 1).

6. Correction

DISM (réparer la référence) puis SFC (réparer les fichiers à partir de la référence). Si échec persistant : réparation sur place (setup.exe de l'ISO de même version, « Conserver les fichiers et applications »), puis P6.4.

7. Validation

  • SFC propre, fonction testée, journal sans nouvelles erreurs.

8. Réponse d'examen modèle

Réponse rédigée attendue

Après une coupure, le menu Démarrer ne s'ouvre plus ; sfc /scannow (invite administrateur) indique « a trouvé des fichiers corrompus, mais n'a pas pu en réparer certains » : la référence de SFC, le magasin de composants, est elle-même abîmée. Je lance DISM /Online /Cleanup-Image /RestoreHealth (« L'opération de restauration s'est terminée correctement »), puis de nouveau sfc /scannow : fichiers réparés. Après redémarrage, un troisième SFC ne trouve aucune violation et le menu Démarrer fonctionne. Comme la panne fait suite à une coupure, je contrôle aussi l'état du disque (journal Système, SMART).

Perd des points : inverser la logique (SFC qui échoue → réinstaller) ; lancer SFC sans droits admin ; dire que SFC « répare le disque ».

9. Pièges et variantes

  • chkdsk répare le système de fichiers, SFC les fichiers système de Windows, DISM le magasin de composants : trois niveaux différents.

P6.4 — Réinitialiser ce PC / réinstaller (Windows) — réinstaller en gardant /home (Linux)

Fréquence : moyen · Gravité : marche 5, la plus lourde

1. Symptômes observables

  • Toutes les marches précédentes ont échoué ; système compromis (malveillant persistant, rançongiciel) ; coût de réparation supérieur à la remise à neuf (accord du client).

2. Causes possibles (classées)

  1. Corruption étendue — OS.
  2. Compromission — sécurité.

3. Questions initiales et sécurité

Attention Réinitialiser/réinstaller supprime les applications (toujours) et, selon l'option, les fichiers personnels. Prérequis OBLIGATOIRES : 1) sauvegarde des données vérifiée (ouverture de fichiers témoins, empreinte si nécessaire), y compris hors des dossiers usuels (messagerie .pst, bases de logiciels, favoris, licences) ; 2) accord écrit du client ; 3) inventaire des logiciels et licences, clé BitLocker, pilotes. Alternative prudente : réparation sur place (ISO même version, « Conserver les fichiers et applications »), qui garde fichiers et programmes.

4. Diagnostic pas à pas

  1. Choisir l'option la moins destructive qui convient : Paramètres → Système → Récupération → Réinitialiser ce PC (Windows 10 : Mise à jour et sécurité → Récupération → Réinitialiser ce PC → Commencer) ; depuis WinRE : Dépannage → Réinitialiser ce PC.

    SI problème logiciel ordinaire → Conserver mes fichiers (applications et paramètres supprimés, fichiers personnels gardés).

    SINON (malveillant, PC qui change de propriétaire) → Supprimer tout (option « Nettoyer les données » si le PC est cédé).

  2. Source : Téléchargement dans le cloud (image propre, plusieurs Go, si les fichiers locaux de Windows sont abîmés) ou Réinstallation locale (sans Internet, utilise les fichiers présents).
  3. Linux : réinstaller en choisissant le partitionnement manuel : / formatée, /home séparée non formatée (point de montage /home, case « formater » décochée), même nom d'utilisateur ; sans /home séparé → sauvegarde et restauration.

5. Test de confirmation

Système propre stable ; la panne d'origine absente.

6. Correction

Après réinitialisation : pilotes, MAJ, logiciels (liste), restauration des données, comptes, imprimantes, protection (antivirus, point de restauration, sauvegarde automatique). Windows dépose une liste « Applications supprimées » sur le Bureau.

7. Validation

  • Données restaurées vérifiées avec le client (fichiers témoins ouverts) ; logiciels métier testés ; Gestionnaire de périphériques propre ; activation ; rapport signé.

8. Réponse d'examen modèle

Réponse rédigée attendue

La réparation du démarrage, la désinstallation des mises à jour, la restauration du système (aucun point) et DISM/SFC hors ligne ont échoué. Je propose une réinitialisation au client. Avant : sauvegarde de C:\Users depuis une clé live sur disque externe, vérifiée par ouverture de fichiers témoins ; export des courriels et de la base du logiciel comptable ; liste des logiciels et licences ; accord écrit. Je choisis « Réinitialiser ce PC → Conserver mes fichiers → Téléchargement dans le cloud » (fichiers locaux de Windows abîmés). Après : pilotes, MAJ, logiciels réinstallés, données contrôlées avec le client, rapport.

Perd des points : réinitialiser en premier ; « Conserver mes fichiers » présenté comme une sauvegarde (on sauvegarde quand même) ; oublier l'accord et la vérification de la sauvegarde.

9. Pièges et variantes

  • « Conserver mes fichiers » ne conserve pas les données enregistrées dans les dossiers des applications (bases locales, C:\NomLogiciel).
  • Réinitialisation qui échoue (« Un problème est survenu lors de la réinitialisation de votre PC ») → réinstallation propre depuis clé (sauvegarde déjà faite).

P6.5 — Linux cassé après une mise à jour : ancien noyau, mode recovery, retour arrière

Fréquence : moyen · Gravité : moyenne à élevée

1. Symptômes observables

  • Après apt upgrade : démarrage bloqué, pilote/graphique cassé, service qui ne démarre plus.

2. Causes possibles (classées)

  1. Nouveau noyau — noyau.
  2. Paquet mis à jour (configuration modifiée) — paquet.
  3. MAJ interrompue — dpkg (P3.6).

3. Questions initiales et sécurité

  • Instantané Timeshift existant ? Sauvegarde de /home ?

4. Diagnostic pas à pas

  1. less /var/log/apt/history.log (ou zless pour les anciens) : ce qui a été mis à jour, quand.
  2. GRUB → Advanced options → noyau précédent.

    SI OK → noyau : garder le précédent, P3.4.

    SINON → (recovery mode) : menu avec clean, dpkg (réparer les paquets), fsck, root (shell ; mount -o remount,rw / pour écrire).

  3. Paquet fautif identifié → réinstaller l'ancienne version : apt list -a paquet, sudo apt install paquet=version, puis sudo apt-mark hold paquet le temps du correctif ; ou restauration Timeshift.

5. Test de confirmation

Avec l'ancienne version, la panne disparaît ; avec la nouvelle, elle revient.

6. Correction

Version stable maintenue (hold temporaire, à retirer : sudo apt-mark unhold paquet) ; configuration comparée à la nouvelle (.dpkg-dist/.dpkg-old).

7. Validation

  • Démarrage normal, fonction testée, hold noté dans le rapport avec date de revue.

8. Réponse d'examen modèle

Réponse rédigée attendue

L'historique apt montre la mise à jour du noyau et du pilote graphique hier. Le démarrage sur le noyau précédent fonctionne : la panne est liée au nouveau noyau. Je laisse le précédent sélectionné, régénère le module du pilote pour le nouveau noyau et, en attendant un correctif, je conserve l'ancien noyau. Je ne supprime pas le noyau qui fonctionne.

9. Pièges et variantes

  • apt autoremove peut supprimer d'anciens noyaux : lire la liste, garder celui en cours (uname -r) et un de secours.
