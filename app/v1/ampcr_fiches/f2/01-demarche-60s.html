1. Face à un problème logiciel : la démarche en 60 secondes

Les six questions à se poser avant toute commande

  1. À quel stade cela casse-t-il ? — firmware (avant le logo Windows / le menu GRUB), chargeur (Windows Boot Manager, GRUB), noyau (logo, écran bleu, (initramfs), kernel panic), système (mode d'urgence, services en échec), ouverture de session (profil, mot de passe), application. Le stade désigne la famille d'outils.

    SI rien ne s'affiche, bips, pas de POST → → Fiche 1 · POST

    SINON (message texte du firmware, du chargeur ou du système) → cette fiche, matrice section 2.

  2. Quel est le message EXACT ? — recopier code (0xc000000f, INACCESSIBLE_BOOT_DEVICE, Code 43, grub rescue>), fichier cité (xxx.sys), heure. Photo de l'écran si possible. Un code se recopie, il ne se résume pas.
  3. Qu'est-ce qui a changé ? — mise à jour Windows/noyau, nouveau pilote, logiciel installé, matériel ajouté, réglage firmware (reset CMOS, mise à jour BIOS), coupure de courant, installation d'un 2e système. 80 % des pannes logicielles suivent un changement : le retour arrière de CE changement est le premier test.
  4. Quel périmètre ? — un utilisateur ou tous ? un programme ou tous ? une seule machine ou plusieurs ? reproductible ou intermittent ? Un seul compte touché → profil/droits ; tous les comptes → système ; plusieurs PC → réseau/serveur/mise à jour commune.
  5. Les données sont-elles à l'abri ? — sauvegarde récente et vérifiée ? BitLocker actif (clé de récupération disponible) ? Accord du client pour toute action qui modifie le disque. → Fiche 5 · Sécurité des données
  6. Quel est le geste le moins invasif qui teste mon hypothèse ? — lire un journal avant de modifier, annuler le dernier changement avant de réparer, réparer avant de restaurer, restaurer avant de réinitialiser.

Ce que l'examinateur attend dans CHAQUE réponse écrite

  • Observation (ce que je vois/lis, cité exactement) → hypothèses classées (la plus probable et la plus simple d'abord) → test discriminant (commande ou geste, résultat attendu, résultat anormal) → conclusion limitée à ce que le test prouve → correction (la moins invasive) → validation (re-test du scénario, journaux propres, utilisateur) → trace (rapport).
  • Précaution avant chaque geste qui modifie le disque ou le démarrage : sauvegarde, accord, identification du bon volume.
  • Jamais « formater », « réinstaller » ou « le disque est HS » comme premier geste ni sur un symptôme non spécifique.

Perd des points : une liste de commandes sans dire ce qu'on attend de chacune ; « je lance sfc » sans dire pourquoi ni comment lire le résultat ; une conclusion sans test ; oublier la validation ; une commande destructive sans avertissement.
