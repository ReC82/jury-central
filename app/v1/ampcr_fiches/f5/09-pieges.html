6. Pièges d'examen et confusions fréquentes

ConfusionComment distinguerCe qu'il faut écrire
Observation / hypothèseL'observation se constate (lire, voir, mesurer) ; l'hypothèse explique et se teste« Observé : … » puis « Hypothèse : … testée par … »
Symptôme / diagnostic« Écran noir » est un symptôme ; « carte graphique HS » est une conclusion qui exige un testJamais de conclusion dans la rubrique Symptômes
Impact / urgenceImpact = combien et quoi est touché ; urgence = délai avant dommageDeux cotes séparées, chacune justifiée par un fait
Urgence ressentie / urgence réelleLe ton ou le rang du demandeur ne change pas la cote ; l'échéance datée, oui« Urgence 2 : échéance demain 9 h »
Escalade fonctionnelle / hiérarchiqueFonctionnelle : vers plus compétent (N2, fabricant) ; hiérarchique : vers qui décide (budget, autorisation, conflit)Type d'escalade + destinataire + motif
Sauvegarde / synchronisationUne synchro reproduit les suppressions et les chiffrementsCopie distincte, vérifiée, idéalement hors ligne
Formatage rapide / effacement sécuriséLe formatage rapide laisse les données récupérablesRéécriture (HDD), effacement sécurisé (SSD) ou destruction, avec attestation
Test / action correctiveUn test produit une information ; une action change l'état (réinstaller n'est pas tester)Tests d'abord, une action à la fois ensuite
Test réussi / cause prouvéeUn test qui ne discrimine pas (redémarrage) peut « marcher » par hasardRésultat attendu écrit avant le test
Panne absente / panne réparéeIntermittente : absence pendant l'intervention ≠ réparationJournal + période d'observation chiffrée
Validation technique / validation utilisateurLa première est faite par le technicien ; la seconde avec les tâches réelles de l'utilisateurLes deux, plus le PV
Rapport / ticketLe ticket suit la demande (statuts) ; le rapport raconte et prouve l'interventionLe rapport cite le n° de ticket
Consignation / simple arrêtArrêté mais branché = 5 V standby présentCordon débranché, décharge, étiquette
Accord oral / accord écritEffacement, ouverture, coût, données : écrit« Accord écrit obtenu le … de … »
Piège Répondre uniquement par la solution technique : sans sécurité, sauvegarde, accord, validation et trace, une réponse juste techniquement reste incomplète.
Piège Recopier l'hypothèse du client comme diagnostic (« virus », « pilote ») : c'est exactement ce que l'énoncé teste souvent.
Piège Un énoncé qui donne une procédure d'entreprise (délais, matrice, seuil d'achat) : c'est elle qui s'applique, pas la convention du cours. Cite-la.
Piège Pannes concomitantes : corriger la première cause ne prouve pas qu'il n'y en a pas une seconde. Refais toujours le test du symptôme initial et vérifie chaque poste ou fonction touché.
Piège « Je change la pièce et on voit » : la substitution n'est un test que si la pièce de rechange est connue bonne et qu'une seule chose change.
Piège Un rapport doit dire ce qui n'a pas été prouvé (limites, risques résiduels) : l'honnêteté est notée.
Piège Données personnelles dans la copie : n'écris jamais un mot de passe, et limite les données personnelles au nécessaire (nom, service, contact).
