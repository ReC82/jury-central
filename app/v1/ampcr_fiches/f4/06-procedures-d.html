3 D. Procédures : domaine, comptes, partages, imprimantes

Règles de décision (groupe de travail / domaine) : groupe de travail = comptes LOCAUX sur chaque PC (pour accéder à un partage de PC-A, il faut un compte de PC-A) ; domaine = comptes centralisés sur le contrôleur de domaine, le poste doit joindre le DC (réseau + DNS + heure). Au-delà d'environ 10 postes ou s'il faut centraliser comptes et stratégies → proposer un domaine. Comptes locaux, UAC, net user local : → Fiche 2 · Commandes.

P3.15 — Ouverture de session de domaine impossible

Fréquence : fréquent · Gravité : bloquante pour l'utilisateur

1. Symptômes observables

  • « Le nom d'utilisateur ou le mot de passe est incorrect. »
  • « Le compte référencé est actuellement verrouillé et vous ne pourrez peut-être pas vous y connecter. » / « Votre compte a été désactivé. Contactez votre administrateur système. » / « Votre mot de passe a expiré et doit être changé. »
  • « La relation d'approbation entre cette station de travail et le domaine principal a échoué. »
  • « Aucun serveur d'authentification n'est actuellement disponible pour traiter la demande d'ouverture de session. » (DC injoignable)

2. Causes possibles (classées)

  1. Utilisateur : Verr. Maj, clavier QWERTY/AZERTY, mauvais compte/domaine (session ouverte en local « .\ » au lieu de « ENTREPRISE\ »).
  2. Compte : mot de passe expiré ou changé ailleurs, verrouillé après trop d'essais, désactivé, horaires d'ouverture.
  3. Poste : canal sécurisé cassé (relation d'approbation), DNS du poste ne pointe pas vers le DC, heure décalée (Kerberos tolère 5 minutes par défaut).
  4. Réseau : poste hors ligne (session en cache possible seulement si déjà ouverte), DC éteint.

3. Questions initiales et sécurité

  • Identité de l'utilisateur vérifiée avant toute réinitialisation de mot de passe (procédure de l'entreprise). Pas de communication de mot de passe par écrit/en clair ; mot de passe temporaire + « doit changer à la prochaine ouverture ».
  • « Avez-vous changé votre mot de passe récemment ? Sur un autre appareil (smartphone qui réessaie l'ancien → verrouillage) ? »

4. Diagnostic pas à pas

  1. Lire le message exact et vérifier la saisie (afficher le mot de passe avec l'œil, Verr. Maj, langue clavier, champ « Se connecter à : ENTREPRISE »).
  2. Même compte sur un autre poste / autre compte sur ce poste.

    SI le compte échoue partout → compte : état dans « Utilisateurs et ordinateurs Active Directory » (verrouillé, désactivé, expiré) — action de l'administrateur.

    SINON (seul ce poste échoue) → poste : étape 3.

  3. Session admin locale sur le poste : ipconfig /all (DNS = DC ?), nltest /dsgetdc:entreprise.local (DC trouvé ?), heure (w32tm /query /status), Test-ComputerSecureChannel (PowerShell admin).

    SI Test-ComputerSecureChannel = False → relation d'approbation cassée.

    SINON SI DNS = box/8.8.8.8 → DC introuvable (corriger DNS) ; écart d'heure > 5 min → resynchroniser.

5. Test de confirmation

Après déverrouillage / correction du DNS / de l'heure / du canal, la session s'ouvre ; whoami renvoie entreprise\jdupont ; whoami /groups liste les groupes attendus.

6. Correction

  • Compte : déverrouiller, réinitialiser avec changement obligatoire, réactiver (droits d'administrateur du domaine, sinon escalade).
  • Relation d'approbation : Test-ComputerSecureChannel -Repair -Credential ENTREPRISE\admin ; à défaut, retirer le poste du domaine (groupe de travail temporaire) puis le rejoindre, redémarrer (compte admin LOCAL connu indispensable avant).
  • Heure : w32tm /resync (le poste se synchronise sur le DC).
  • DNS : DNS du poste = IP du DC (via DHCP de préférence).

7. Validation

Ouverture de session, lecteurs réseau montés, gpupdate /force sans erreur, accès aux ressources ; l'utilisateur change son mot de passe temporaire.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Le message indique que le compte est verrouillé. Je vérifie avec l'utilisateur : il a changé son mot de passe hier et son smartphone continue d'utiliser l'ancien pour la messagerie, ce qui provoque des échecs répétés. Après vérification de son identité, l'administrateur déverrouille le compte ; je mets à jour le mot de passe sur le smartphone. Validation : ouverture de session réussie, plus de verrouillage le lendemain. »

Perd des points : réinstaller le poste ; réinitialiser un mot de passe sans vérifier l'identité ; confondre compte local et compte du domaine.

9. Pièges et variantes

Piège Portable hors du bureau : il ouvre la session avec les identifiants en cache, mais si le mot de passe a été changé ailleurs, l'ANCIEN fonctionne hors ligne et le nouveau non. Un poste restauré depuis une ancienne image = relation d'approbation cassée typique.

P3.16 — La jonction d'un poste au domaine échoue

Fréquence : fréquent en installation · Gravité : moyenne

1. Symptômes observables

  • sysdm.cpl → Modifier → Domaine « entreprise.local » → « Un contrôleur de domaine Active Directory (AD DC) pour le domaine “entreprise.local” n'a pas pu être contacté. »
  • Ou : « Accès refusé » (compte sans droit de jonction), « Le nom d'ordinateur existe déjà ».

2. Causes possibles (classées)

  1. DNS du poste = box ou DNS public → l'enregistrement du DC (SRV) est introuvable.
  2. DC injoignable (réseau, VLAN, pare-feu).
  3. Édition Windows Famille (ne peut pas joindre un domaine : il faut Professionnel/Entreprise/Éducation).
  4. Compte utilisé sans droit de jonction, nom d'ordinateur en double.
  5. Heure très décalée.

3. Questions initiales et sécurité

  • Compte autorisé à joindre des postes ; nom d'ordinateur conforme à la convention ; compte admin local connu (en cas d'échec après redémarrage).

4. Diagnostic pas à pas

  1. Édition de Windows (Paramètres → Système → Informations système).

    SI Famille → mise à niveau Pro nécessaire.

    SINON → étape 2.

  2. nslookup entreprise.local — attendu : IP du DC.

    SI échec / « Serveur : box » → DNS : corriger vers l'IP du DC.

    SINON → ping du DC, heure, compte utilisé.

5. Test de confirmation

nslookup -type=SRV _ldap._tcp.dc._msdcs.entreprise.local renvoie le DC une fois le bon DNS configuré.

6. Correction

DNS = IP du DC ; puis Paramètres → Système → Informations système → « Domaine ou groupe de travail » (sysdm.cpl → Modifier) → Domaine → identifiants autorisés → redémarrer. PowerShell : Add-Computer -DomainName entreprise.local -Credential ENTREPRISE\admin -Restart.

7. Validation

Message « Bienvenue dans le domaine entreprise.local », redémarrage, ouverture de session avec un compte du domaine, objet ordinateur présent dans AD, gpupdate /force OK.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Le poste reçoit son DNS de la box (192.168.1.1), qui ne connaît pas le domaine interne entreprise.local : nslookup entreprise.local échoue, donc Windows ne trouve aucun contrôleur de domaine. Je configure le DNS du poste sur le contrôleur de domaine 192.168.1.10 (idéalement dans les options du DHCP), nslookup répond alors avec l'adresse du DC, et la jonction réussit. Je redémarre et j'ouvre une session avec un compte du domaine. »

Perd des points : mettre le DNS en 8.8.8.8 ; oublier le redémarrage ; tenter la jonction avec Windows Famille.

9. Pièges et variantes

Piège Domaine DNS (entreprise.local, nom) ≠ domaine d'administration (ensemble des comptes et stratégies) — mais c'est le même nom qu'on saisit. « Groupe de travail WORKGROUP » identique sur tous les PC n'apporte AUCUNE authentification commune : seulement la découverte.

P3.17 — « Windows ne peut pas accéder à \\SRV01 » : chemin réseau introuvable (0x80070035 / erreur 53)

Fréquence : très fréquent · Gravité : bloquante pour l'accès aux fichiers

1. Symptômes observables

  • Explorateur : « Windows ne peut pas accéder à \\SRV01\Compta … Code d'erreur : 0x80070035. Le chemin d'accès réseau n'a pas été trouvé. »
  • net use P: \\SRV01\Compta → « Erreur système 53. Le chemin réseau n'a pas été trouvé. »
  • Variante : « Erreur système 67. Nom de réseau introuvable. » (le serveur répond mais le NOM DU PARTAGE n'existe pas).

2. Causes possibles (classées)

  1. Nom du serveur non résolu (DNS, NetBIOS désactivé, pas de suffixe) → par IP ça marche.
  2. Serveur éteint / injoignable (réseau).
  3. Port SMB 445 bloqué : pare-feu du serveur (règle « Partage de fichiers et d'imprimantes »), profil Public sur le client ou le serveur, pare-feu tiers.
  4. Service « Serveur » (LanmanServer) arrêté sur l'hôte ; service « Station de travail » arrêté sur le client.
  5. Partage supprimé ou renommé (→ erreur 67), faute de frappe.
  6. NAS ancien en SMBv1 seulement (désactivé sur Windows 10/11 récents).

3. Questions initiales et sécurité

  • « Tous les postes ou un seul ? Le partage a-t-il fonctionné ? Un changement (box, serveur renommé) ? »

4. Diagnostic pas à pas

  1. ping SRV01.

    SI « n'a pas pu trouver l'hôte » → essayer ping 192.168.1.10 et \\192.168.1.10\Compta : si l'IP fonctionne → résolution de nom (P3.7).

    SINON (nom résolu) → étape 2.

  2. Le serveur répond-il ? (ping ou arp -a)

    SI non → serveur éteint/réseau.

    SINON → étape 3.

  3. Test-NetConnection SRV01 -Port 445.
    ComputerName     : SRV01
RemoteAddress    : 192.168.1.10
RemotePort       : 445
InterfaceAlias   : Ethernet
SourceAddress    : 192.168.1.37
TcpTestSucceeded : False

    SI False → SMB injoignable : si AUCUN poste n'accède → serveur (service Serveur, pare-feu du serveur) ; si SEUL ce poste échoue → ce poste (profil Public, pare-feu sortant, antivirus).

    SINON (True) → nom du partage : net view \\SRV01 liste les partages ; erreur 67 → partage renommé/supprimé.

5. Test de confirmation

Après correction de la cause, TcpTestSucceeded : True et net use réussit. Erreur 53 ≠ erreur 5 : avec 53, on n'atteint même pas l'étape des droits — ne pas toucher aux permissions.

6. Correction

  • Nom : DNS / suffixe (P3.7) ; contournement temporaire par IP.
  • Pare-feu : profil Privé/Domaine, règle « Partage de fichiers et d'imprimantes » activée (serveur), pare-feu tiers.
  • Services : services.msc → « Serveur » (hôte) et « Station de travail » (client) démarrés, type Automatique.
  • Partage : recréer/renommer (P3.19). NAS SMBv1 : mettre à jour le NAS (activer SMB2/3) plutôt que réactiver SMBv1 (faille de sécurité).

7. Validation

Port 445 True, net use P: \\SRV01\Compta /persistent:yes → « La commande s'est terminée correctement. », ouverture d'un fichier, test depuis un second poste.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Sur le portable de Tom, ping SRV01 est résolu en 192.168.1.10 et répond : le DNS, l'adresse IP et le réseau fonctionnent. Test-NetConnection SRV01 -Port 445 renvoie False : le service de partage SMB n'est pas joignable depuis ce poste. L'erreur 53 indique “chemin réseau introuvable”, pas “accès refusé” (erreur 5) : les droits ne sont pas en cause. Les autres postes ouvrent les partages, donc le serveur fonctionne : le blocage est du côté du portable, dont la connexion est passée en profil Public avec la nouvelle box. Je repasse le profil en Privé, le test du port 445 donne True, net use P: réussit et Tom ouvre un fichier. »

Perd des points : modifier les permissions NTFS pour une erreur 53 ; « réinstaller le serveur » alors que les autres postes y accèdent.

9. Pièges et variantes

Piège La découverte du réseau (voir les PC dans « Réseau ») est désactivée en profil Public et dépend de services (Hôte du fournisseur de découverte de fonctions, Publication des ressources de découverte de fonctions) : un PC absent de la liste « Réseau » peut être parfaitement accessible par \\NOM ou \\IP. Ne pas diagnostiquer sur l'absence dans la liste.

P3.18 — « Accès refusé » ou lecture seule : calculer le droit effectif (partage + NTFS)

Fréquence : très fréquent (et très fréquent à l'examen) · Gravité : moyenne ; sécurité des données en jeu

1. Symptômes observables

  • « Vous n'avez actuellement pas l'autorisation d'accéder à ce dossier » / « Accès refusé » / « Erreur système 5. L'accès est refusé. »
  • L'utilisateur ouvre les fichiers mais « Vous avez besoin d'une autorisation pour effectuer cette action » à l'enregistrement → lecture seule.
  • Un stagiaire voit un dossier qu'il ne devrait pas voir (droits trop larges).

2. Causes possibles (classées)

  1. Permission de PARTAGE plus restrictive que la NTFS (ex. Tout le monde : Lecture par défaut).
  2. Permission NTFS insuffisante pour l'utilisateur et ses groupes.
  3. Refus explicite (Refuser) hérité d'un groupe dont l'utilisateur fait partie.
  4. Utilisateur ajouté au groupe mais session non rouverte (le jeton d'accès contient les groupes du moment de l'ouverture de session).
  5. Connexion au partage avec d'autres identifiants mémorisés (P3.20).
  6. Héritage désactivé sur un sous-dossier, fichier ouvert/verrouillé par un autre utilisateur.

3. Questions initiales et sécurité

  • « Quel accès est NÉCESSAIRE (lire ? modifier ? supprimer ?) et validé par le responsable des données ? » Moindre privilège : jamais « Tout le monde : Contrôle total » pour « faire fonctionner ». Relever les permissions existantes avant modification.

4. Diagnostic pas à pas : le calcul en 4 temps

  1. Lister les groupes de l'utilisateur : whoami /groups (sur sa session) ou net user jdupont /domain (ligne « Appartient aux groupes globaux »).
  2. Couche PARTAGE (Propriétés → Partage → Partage avancé → Autorisations) : additionner les autorisations de l'utilisateur ET de tous ses groupes → la plus large l'emporte (cumul), SAUF un « Refuser » qui l'emporte sur tout.
  3. Couche NTFS (Propriétés → Sécurité ; « Avancé » → onglet « Accès effectif ») : même règle de cumul + refus prioritaire.
  4. Droit effectif à travers le réseau = le PLUS RESTRICTIF des deux résultats. En local (session ouverte sur le serveur lui-même) seule la NTFS s'applique.

6. Correction

  • Bonne pratique : partage = « Utilisateurs authentifiés » ou les groupes concernés en Modifier (ou Contrôle total pour les admins), et le contrôle fin en NTFS ; ou partage aussi précis que la NTFS.
  • Accorder au GROUPE (pas à l'individu) : ajouter l'utilisateur au groupe Compta ; retirer un refus inutile (préférer « ne pas autoriser » à « Refuser »).
  • L'utilisateur ferme et rouvre sa session (ou klist purge + reconnexion) pour que le nouveau groupe soit pris en compte.
  • Commandes : icacls D:\Partages\Compta /grant "ENTREPRISE\Compta:(OI)(CI)M" ; Grant-SmbShareAccess -Name Compta -AccountName "ENTREPRISE\Compta" -AccessRight Change.

7. Validation

L'utilisateur crée, modifie, enregistre un fichier test puis le supprime ; un compte qui ne doit PAS accéder est bien refusé (test négatif) ; documenter la modification (qui, quoi, validé par qui).

8. Réponse d'examen modèle

Réponse rédigée attendue

« Léa est membre des groupes Compta et Stagiaires. Permissions de partage : Compta = Modifier, donc Modifier pour Léa. Permissions NTFS : Compta = Modification, mais Stagiaires = Refuser Modification ; le refus explicite l'emporte sur l'autorisation, son droit NTFS est donc Lecture et exécution. À travers le réseau, le droit effectif est le plus restrictif des deux couches : Lecture. Cela explique qu'elle ouvre les fichiers sans pouvoir enregistrer. Si le responsable confirme qu'elle doit modifier, je la retire du groupe Stagiaires (ou je supprime ce refus s'il n'a plus de raison d'être), elle rouvre sa session, et je vérifie qu'elle peut créer et modifier un fichier test, puis qu'un autre stagiaire reste en lecture. »

Perd des points : additionner partage et NTFS ; prendre « le plus permissif des deux couches » ; donner Contrôle total à Tout le monde ; oublier la reconnexion après ajout au groupe ; ignorer le Refuser.

9. Pièges et variantes

Piège Le cumul (le plus large) s'applique À L'INTÉRIEUR d'une couche ; le plus restrictif s'applique ENTRE les deux couches. Le Refuser explicite bat l'Autoriser explicite ; nuance rare : une autorisation explicite posée sur l'objet l'emporte sur un refus seulement hérité du dossier parent. Linux/Samba : droits Unix rwx (ex. drwxrwx--- propriétaire et groupe en lecture-écriture, autres rien) combinés aux droits Samba (read only = no, valid users = @compta) : même logique du plus restrictif.

  3. Panneau de configuration → Gestionnaire d'identification → Informations d'identification Windows : entrée pour SRV01 avec un ancien compte/mot de passe ?

6. Correction

8. Réponse d'examen modèle

Réponse rédigée attendue

« L'erreur 1219 signifie qu'une connexion au serveur existe déjà avec un autre compte : net use montre \\SRV01\Scans connecté avec le compte “scanner”. Après avoir fait fermer les documents ouverts, je supprime cette connexion et l'identifiant mémorisé (cmdkey /delete:SRV01), puis je reconnecte P: avec le compte de l'utilisatrice. Je vérifie après redémarrage que P: se reconnecte seul. »

Perd des points : modifier les permissions du serveur pour une erreur d'identifiants côté client.

9. Pièges et variantes

Piège \\SRV01 et \\192.168.1.10 sont vus comme deux serveurs différents par Windows : moyen de contournement (tester un autre compte par IP), mais source de confusion. Croix rouge ≠ panne.

P3.21 — Imprimante réseau « Hors connexion » (ou ping OK mais n'imprime pas)

Fréquence : très fréquent · Gravité : moyenne

1. Symptômes observables

  • File d'attente : « Imprimante hors connexion », documents « Erreur – Impression » ou en attente ; tous les postes ou un seul.
  • Souvent après remplacement de la box, coupure de courant, déménagement de l'imprimante.

2. Causes possibles (classées)

  1. Imprimante éteinte, en veille profonde, bourrage/papier/toner (panneau en erreur).
  2. Adresse IP de l'imprimante changée (DHCP, nouvelle box) alors que les postes visent l'ancienne dans leur port TCP/IP.
  3. Imprimante sur le Wi-Fi déconnectée (changement de clé) / câble.
  4. Adresse fixe de l'imprimante dans un ancien réseau (nouvelle box avec un autre réseau).
  5. Protocole SNMP de statut qui signale à tort « hors connexion ».
  6. Pilote (P3.22).

3. Questions initiales et sécurité

  • « Tous les postes ? Depuis quand ? Changement de box ? » Documents confidentiels en file : ne pas les réimprimer sans accord.

4. Diagnostic pas à pas

  1. Panneau de l'imprimante : allumée, prête, sans erreur ; imprimer la page de configuration réseau (adresse, masque, passerelle, DHCP/statique).
  2. Comparer avec le port des postes : Propriétés de l'imprimante → Ports → « Standard TCP/IP Port » → adresse (PowerShell : Get-PrinterPort).

    SI adresses différentes (port 192.168.1.50, imprimante 192.168.1.137) → adresse changée : correction.

    SINON → étape 3.

  3. ping de l'adresse de l'imprimante.

    SI « Impossible de joindre l'hôte de destination » (réponse de sa propre IP) → personne à cette adresse : imprimante absente du réseau (câble, Wi-Fi, autre réseau).

    SINON (ping OK) → Test-NetConnection 192.168.1.50 -Port 9100 (RAW) ; ouvrir http://192.168.1.50 (interface web) ; désactiver « État SNMP activé » dans le port si le statut est faux.

5. Test de confirmation

Page de configuration ≠ adresse du port ; après mise à jour du port, page de test OK. Limite : une imprimante peut ne pas répondre au ping et imprimer quand même (port 9100 ouvert).

6. Correction

  • Adresse fixe HORS étendue dans la plage imprimantes (ex. 192.168.1.20) sur le panneau / interface web, ou réservation DHCP sur la box (MAC de l'imprimante → 192.168.1.20).
  • Mettre à jour le port TCP/IP de chaque poste (Propriétés de l'imprimante → Ports → Ajouter un port → Standard TCP/IP Port), ou mieux : partager l'imprimante depuis un serveur (\\SRV01\Traceur-A1) → un seul port à maintenir.
  • Relancer les documents en attente ou les supprimer avec l'accord des utilisateurs ; mettre à jour le plan d'adressage.

7. Validation

Page de test depuis CHAQUE poste (ou au moins deux), file vide, statut « Prêt », adresse stable après redémarrage de l'imprimante et de la box.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Les postes impriment vers le port 192.168.1.50 ; la page de configuration du traceur indique 192.168.1.137, obtenue par DHCP : la nouvelle box a redistribué les adresses et le traceur a changé d'adresse. Le ping de 192.168.1.50 répond “Impossible de joindre l'hôte de destination” : plus personne n'a cette adresse, d'où l'état hors connexion. Je donne au traceur l'adresse fixe 192.168.1.20, hors de l'étendue DHCP, puis je mets à jour le port TCP/IP des postes (ou je partage le traceur depuis le serveur pour n'avoir qu'un port à tenir à jour). Vérification : page de test depuis chaque poste, documents en attente relancés, plan d'adressage mis à jour. »

Perd des points : réinstaller le pilote d'emblée ; fixer une adresse DANS l'étendue ; ne vérifier que depuis un seul poste.

9. Pièges et variantes

Piège Un seul poste en « hors connexion » alors que les autres impriment → port/pilote de CE poste (ou hôte de partage éteint s'il passe par un PC). Imprimante Wi-Fi : après changement de clé Wi-Fi, elle ne se reconnecte pas seule → reconfigurer son Wi-Fi depuis le panneau (WPS désactivé = saisir la clé).

P3.22 — File d'impression bloquée, spouleur, pilote ou imprimante partagée

Fréquence : fréquent · Gravité : faible à moyenne

1. Symptômes observables

  • Un document en « Erreur » en tête de file, les suivants bloqués ; impossible de supprimer (« Suppression… » indéfiniment).
  • Connexion à \\PC-ACCUEIL\HP-Accueil : « Windows ne peut pas se connecter à l'imprimante » (ex. code 0x0000011b, 0x00000709), demande d'installation de pilote, accès refusé.
  • Service « Spouleur d'impression » arrêté → aucune imprimante visible.

2. Causes possibles (classées)

  1. Document corrompu/volumineux bloquant la file.
  2. Service Spouleur planté.
  3. Pilote absent pour l'architecture du client (x64), pilote incompatible, installation de pilote bloquée sans droits admin (durcissement de sécurité Windows).
  4. PC hôte du partage éteint, en veille, pare-feu (profil Public).
  5. Permissions de l'imprimante partagée (onglet Sécurité : Imprimer) .

3. Questions initiales et sécurité

  • Le vidage de file supprime les travaux de TOUS les utilisateurs : prévenir.

4. Diagnostic pas à pas

  1. Ouvrir la file → annuler le document en erreur.

    SI la file repart → document fautif.

    SINON → étape 2.

  2. services.msc → Spouleur d'impression : état.

    SI arrêté/bloqué → redémarrage et vidage (correction).

    SINON → étape 3.

  3. Imprimante partagée : l'hôte est allumé, ping, accès \\PC-ACCUEIL ; onglet Partage (« Partager cette imprimante ») ; pilote installé pour x64 ; permission « Imprimer » pour le groupe.

5. Test de confirmation

Page de test après redémarrage du spouleur ; l'impression repart.

6. Correction

Attention La suppression du contenu de C:\Windows\System32\spool\PRINTERS efface tous les travaux en attente de tous les utilisateurs. Prérequis : utilisateurs prévenus, service arrêté avant suppression. Alternative prudente : annuler d'abord les documents un par un depuis la file, puis simple redémarrage du service.

C:\> net stop spooler
C:\> del /Q C:\Windows\System32\spool\PRINTERS\*
C:\> net start spooler
  • Pilote : installer le pilote du fabricant (bonne architecture) en administrateur sur le client, puis reconnecter l'imprimante partagée ; maintenir hôte et clients à jour (ne pas désactiver les protections de sécurité de l'impression).
  • Hôte de partage : alimentation/veille désactivée, profil Privé, ou passer à une imprimante IP directe / serveur d'impression.

7. Validation

Page de test, impression d'un document réel depuis l'application de l'utilisateur, file vide, service Spouleur en démarrage Automatique.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Le premier document de la file est en état “Erreur” et bloque les suivants ; il refuse de s'annuler. J'informe les utilisateurs que la file va être vidée, j'arrête le service Spouleur d'impression, je supprime les fichiers du dossier spool\PRINTERS, je redémarre le service, puis j'imprime une page de test et je fais relancer les documents nécessaires. »

Perd des points : supprimer le spool sans arrêter le service ni prévenir ; réinstaller Windows.

9. Pièges et variantes

Piège Imprimante partagée par un PC : si ce PC est éteint, TOUS les autres sont « hors connexion » → ce n'est pas l'imprimante. Scanner réseau vers dossier partagé en échec = souvent mot de passe du compte de numérisation changé ou SMBv1 seul sur le copieur.
