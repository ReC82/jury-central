Erreurs de méthode qui coûtent des points

  • Changer la configuration IP alors que le lien physique est absent (« Média déconnecté »).
  • Commencer par ping www.google.be : un échec ne dit pas si c'est le DNS ou la connectivité ; suivre l'ordre 127.0.0.1 → propre IP → passerelle → 8.8.8.8 → nom.
  • Croire que ping 127.0.0.1 ou le ping de sa propre IP testent la carte ou le câble : ils ne sortent pas du poste.
  • Lire les statistiques du ping (« reçus = 4 ») au lieu de l'adresse qui répond.
  • Conclure « carte HS », « switch HS », « box HS » sur un seul symptôme, sans permutation (cordon, port, poste voisin).
  • « Désactiver le pare-feu » ou « Tout le monde : Contrôle total » comme solution définitive.
  • Fixer une adresse dans l'étendue DHCP ; attribuer l'adresse réseau ou de diffusion à un hôte ; passerelle hors du réseau du poste.
  • Mettre 8.8.8.8 comme DNS sur un poste de domaine.
  • Additionner permissions de partage et NTFS, ou prendre la plus permissive des deux.
  • Oublier la validation (refaire toute la chaîne de tests + test métier) et la mise à jour du plan d'adressage / de la documentation.
  • Redémarrer la box ou faire un reset usine sans relever les voyants ni sauvegarder la configuration.
  • ipconfig /release lancé à distance (prise en main) : tu perds la connexion au poste.

Confusions de vocabulaire à ne pas commettre à l'écrit

Ne pas confondreRègle pratique
Protocole / service / équipementDHCP est un protocole, le « serveur DHCP » un service, la box l'équipement qui l'héberge. Écrire « le service DHCP de la box ne répond pas », pas « le DHCP est cassé ».
Hub / switch / routeurHub = répète (couche 1, collisions) ; switch = adresses MAC (couche 2) ; routeur = adresses IP, relie des réseaux (couche 3).
Passerelle / DNSPasserelle = où envoyer les paquets hors réseau ; DNS = qui traduit les noms. Peuvent être la même box, mais ce sont deux réglages distincts.
Point d'accès / répéteur / routeur Wi-FiAP = relié en câble ; répéteur = sans câble, réémet ; routeur Wi-Fi = crée un réseau et un DHCP (à passer en mode AP).
Groupe de travail / domaineGroupe de travail = comptes locaux sur chaque PC, aucune authentification commune ; domaine = comptes centralisés sur le DC, poste joint, DNS = DC.
Domaine DNS / domaine WindowsMême nom (entreprise.local) mais le premier sert à résoudre des noms, le second à gérer comptes et stratégies.
Adresse MAC / IPMAC = 6 octets hexadécimaux, carte, segment local ; IPv4 = 4 nombres 0–255, routable, configurée.
NetBEUI / TCP/IPNetBEUI : historique, non routable, petits réseaux locaux uniquement ; TCP/IP : routable, standard actuel.
Débit radio / débit utile« 866 Mbit/s » affiché = débit de liaison ; le débit réel mesuré est nettement inférieur.

Pannes concomitantes et intermittentes : réflexes

  • Corriger une cause puis REFAIRE toute la chaîne de tests : une seconde panne peut se cacher derrière (masque faux ET passerelle fausse ; DNS faux ET heure fausse).
  • Intermittent : ping -t horodaté par l'observation, relever les horaires, chercher ce qui change (appareil allumé, sauvegarde, micro-ondes, conflit IP, bail DHCP qui expire, canal DFS).
  • Symptôme général + cause locale possible : conflit avec l'IP de la passerelle, boucle de câblage, DHCP parasite.
