3 C. Procédures : deux PC en direct, mini-réseau, switch et VLAN

P3.12 — Relier deux PC en direct (et dépanner quand ils ne se voient pas)

Fréquence : classique d'examen · Gravité : faible

1. Symptômes observables

  • Deux PC reliés par un câble RJ45 : pas de voyant, ou voyant mais ping KO, ou ping OK mais partage inaccessible.

2. Causes possibles (classées)

  1. Adresses incohérentes : un PC en DHCP (169.254.x.x/16) et l'autre en statique 192.168.10.x/24 → réseaux différents.
  2. Pare-feu (profil Public) bloque ping et partage → P3.9.
  3. Câble droit entre deux cartes anciennes (10/100) sans Auto MDI-X → pas de lien ; il faut un croisé (les cartes Gigabit gèrent l'Auto MDI-X).
  4. Câble défectueux (F3).
  5. Partage non créé / compte sans droit / identifiants (le PC distant exige un compte LOCAL de ce PC avec mot de passe).

3. Questions initiales et sécurité

  • But (copier des données ? jouer ? migrer ?) → partage temporaire, droits minimaux, arrêt du partage à la fin. Sauvegarde des données avant une copie massive.

4. Diagnostic pas à pas

  1. Voyants des deux cartes.

    SI aucun lien → câble (tester, F3) ; cartes 10/100 anciennes → câble croisé.

    SINON → étape 2.

  2. ipconfig sur les deux.

    SI 169.254.x.x d'un côté et 192.168.10.x de l'autre → mettre les deux en statique dans le MÊME réseau.

    SINON (même réseau) → étape 3.

  3. ping dans les deux sens.

    SI « Délai d'attente » → pare-feu (profil Public) : P3.9.

    SINON (« Impossible de joindre l'hôte » depuis sa propre IP) → l'autre ne répond pas à l'ARP : adresse mal tapée, carte désactivée.

  4. Accès au partage \\192.168.10.1\Agenda (par IP : pas besoin de DNS).

5. Test de confirmation

Avec 192.168.10.1/24 et 192.168.10.2/24, sans passerelle, ping OK dans les deux sens et arp -a montre la MAC de l'autre PC.

6. Correction (procédure de mise en service)

  1. Câble RJ45 testé (droit si Auto MDI-X, croisé T568A/T568B pour matériel ancien — → Fiche 3 · RJ45).
  2. PC-A : 192.168.10.1, masque 255.255.255.0, passerelle VIDE, DNS vide. PC-B : 192.168.10.2, même masque. (netsh interface ipv4 set address name="Ethernet" static 192.168.10.1 255.255.255.0.)
  3. Profil réseau Privé sur les deux (ou règle d'écho ICMP + partage de fichiers).
  4. Sur le PC source : clic droit sur le dossier → Propriétés → Partage → Partage avancé → Partager ce dossier → Autorisations (Lecture pour le compte prévu) ; un compte local avec mot de passe sur ce PC.
  5. Sur l'autre PC : Explorateur → \\192.168.10.1\Agenda → identifiants PC-A\compte.

7. Validation

Ping dans les deux sens ; ouverture d'un fichier copié (intégrité) ; arrêt du partage temporaire et retour à la configuration DHCP initiale si les PC retournent sur le réseau de l'entreprise.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Relevé 1 : le portable a 169.254.12.40/16 (APIPA, aucun DHCP sur un lien direct) et PC-ACCUEIL 192.168.10.1/24 : ils ne sont pas dans le même réseau. Je configure le portable en 192.168.10.2, masque 255.255.255.0, sans passerelle ni DNS (réseau isolé). Le ping répond alors “Délai d'attente dépassé” : la demande part, mais PC-ACCUEIL ne répond pas ; arp -a montre sa MAC, c'est son pare-feu qui bloque, la connexion étant en profil Public. Je passe le profil en Privé : réponses. Je partage le dossier Agenda en lecture pour le compte prévu, je l'ouvre en \\192.168.10.1\Agenda avec un compte de PC-ACCUEIL, je copie, j'ouvre un fichier copié pour vérifier, puis j'arrête le partage temporaire. »

Perd des points : mettre une passerelle « 192.168.1.1 » ; affirmer qu'un câble croisé est OBLIGATOIRE avec des cartes Gigabit ; partager « Tout le monde – Contrôle total ».

9. Pièges et variantes

Piège Les deux PC en DHCP sans serveur : chacun prend 169.254.x.x/16 et ils PEUVENT communiquer (même réseau) — solution acceptable mais lente à apparaître et non maîtrisée ; préférer le statique. Adresses .0 ou .255 en /24 interdites (réseau / diffusion). Linux en face : partage Samba, accès smb://192.168.10.1/Agenda.

P3.13 — Mettre en service un mini-réseau (3 à 20 postes) / deux groupes de postes qui ne communiquent pas

Fréquence : classique d'examen · Gravité : moyenne

1. Symptômes observables

  • Création : le client veut relier 5 PC, une imprimante, un NAS et Internet.
  • Panne : les postes du premier étage voient le NAS mais pas ceux du rez ; plan d'adressage incohérent (masques ou plages différents).

2. Causes possibles (classées)

  1. Plan d'adressage incohérent : deux réseaux IP différents sur le même switch sans routeur (ex. 192.168.1.0/24 et 192.168.2.0/24).
  2. Adresses fixes dans l'étendue DHCP, adresse réseau/diffusion attribuée à un hôte.
  3. Un hub/switch en cascade éteint ou mal relié (lien inter-switch).
  4. Second DHCP (P3.3), VLAN (P3.14).

3. Questions initiales et sécurité

  • Nombre de postes actuels et futurs, équipements à adresse fixe (NAS, imprimante, serveur, AP), Wi-Fi invités, distances (100 m max par segment cuivre), emplacement de la box.

4. Diagnostic pas à pas (contrôle d'un plan)

  1. Calculer l'adresse réseau de CHAQUE hôte (adresse ET masque, voir 4 A).

    SI deux réseaux différents sans routeur → incohérence : renuméroter dans un seul réseau, ou ajouter un routeur si la séparation est voulue.

    SINON → étape 2.

  2. Vérifier chaque adresse fixe : dans le réseau, hors étendue DHCP, ni adresse réseau ni diffusion, pas de doublon.
  3. Vérifier passerelle et DNS : même valeur sur tous les postes, passerelle dans le réseau.
  4. Vérifier la topologie physique : chaque switch alimenté, liaisons inter-switch actives, pas de boucle.

5. Test de confirmation

Tableau du plan : pour chaque ligne, réseau calculé identique ; un ping croisé entre un poste de chaque groupe réussit après correction.

6. Correction : plan type d'un mini-réseau 192.168.1.0/24

  2. Masque 255.255.255.0 partout, passerelle 192.168.1.1, DNS 192.168.1.1 (ou serveur interne).
  3. Choix d'équipement : switch (pas hub) pour multiplier les prises ; routeur/box pour Internet et séparer des réseaux ; AP pour le Wi-Fi (tableau 4 B).
  4. Repérage des prises et du brassage (→ Fiche 3 · Installation).
  5. Documenter : schéma, plan d'adressage, identifiants d'administration en lieu sûr.

7. Validation (recette)

Pour chaque poste : ipconfig conforme au plan, ping passerelle, ping NAS, ping 8.8.8.8, ping nom ; accès au partage avec le compte prévu ; page de test de l'imprimante ; Wi-Fi : connexion d'un portable et d'un smartphone ; procès-verbal signé.

8. Réponse d'examen modèle

Réponse rédigée attendue (contrôle d'un plan)

« Le PC-05 est configuré en 192.168.2.15/24 : son réseau est 192.168.2.0/24 alors que tous les autres équipements sont dans 192.168.1.0/24. Sans routeur entre ces deux réseaux, il ne peut pas joindre le NAS ni la passerelle. L'imprimante en 192.168.1.150 est dans l'étendue DHCP (.100 à .199) : risque de conflit. Corrections : PC-05 en DHCP (ou 192.168.1.15 si une adresse fixe est exigée, hors étendue) ; imprimante en 192.168.1.20 (plage des imprimantes) avec mise à jour des ports d'impression. Vérification : ping croisés PC-05 ↔ NAS, page de test, plan mis à jour. »

Perd des points : attribuer 192.168.1.0 ou 192.168.1.255 à un hôte ; oublier de vérifier les adresses fixes par rapport à l'étendue ; proposer un hub.

9. Pièges et variantes

Piège Deux réseaux IP sur le MÊME switch : physiquement reliés, logiquement séparés → il faut un routeur (ou renuméroter), un switch ne route pas. À l'inverse, deux postes dans le même réseau IP mais sur deux switchs NON reliés ne se verront pas : vérifier le câble inter-switch.

P3.14 — Port de switch, VLAN, brassage, boucle

Fréquence : occasionnel (réseaux avec switch administrable) · Gravité : locale (VLAN) à totale (boucle)

1. Symptômes observables

  • Le poste fonctionne sur une prise, pas sur une autre : 169.254 ou adresse d'un autre réseau (réseau invités, téléphonie).
  • Boucle : tout le réseau s'effondre juste après l'ajout d'un câble, voyants de tous les ports qui clignotent en continu, CPU des postes en hausse, pings perdus partout.

2. Causes possibles (classées)

  1. Prise brassée sur un port d'un autre VLAN (ex. VLAN 20 invités au lieu de VLAN 10 bureau) ou sur le mauvais switch.
  2. Port désactivé (shutdown) ou bloqué par la sécurité de port (MAC non autorisée).
  3. Câble reliant deux prises du même réseau / deux ports du même switch → boucle sans STP.
  4. Petit switch de bureau non administrable ajouté qui crée une boucle avec un second câble.

3. Questions initiales et sécurité

  • Accès au switch administrable = droits d'administrateur réseau : intervention à demander/escalader ; relever la configuration du port avant modification.

4. Diagnostic pas à pas

  1. Brancher un poste connu sur la prise suspecte, et le poste suspect sur une prise connue.

    SI le défaut suit la PRISE → brassage/port/VLAN : étape 2.

    SINON → le défaut suit le POSTE : configuration du poste.

  2. Suivre le repérage : prise B12 → panneau de brassage port 12 → port du switch ; voyant du port.
  3. Configuration du port sur le switch (interface web) : VLAN d'accès, état, sécurité.

    SI VLAN ≠ VLAN prévu pour les postes → corriger.

    SINON port désactivé / « err-disabled » → réactiver après avoir compris la cause.

  4. Boucle : débrancher le dernier câble ajouté (ou débrancher un à un les petits switchs) jusqu'au retour à la normale.

5. Test de confirmation

Le même poste obtient une adresse du bon réseau sur le port corrigé ; pour la boucle, le réseau revient dès le retrait du câble et retombe si on le remet (ne pas répéter inutilement).

6. Correction

  • Rebrasser sur un port du bon VLAN ou modifier le VLAN d'accès du port ; mettre à jour l'étiquetage et le cahier de brassage.
  • Supprimer la liaison redondante ; activer STP/RSTP si les switchs le permettent (redondance voulue) ; interdire les switchs personnels.

7. Validation

Adresse dans la bonne plage, ping passerelle/serveur ; voyants normaux ; ping continu stable sur plusieurs postes pendant quelques minutes.

8. Réponse d'examen modèle

Réponse rédigée attendue

« Le portable obtient 192.168.20.34 (réseau invités) sur la prise B12 et 192.168.10.x sur la prise B11 : le défaut suit la prise, pas le poste. Le repérage indique que B12 est brassée sur le port 12 du switch, configuré dans le VLAN 20 (invités). Je demande à l'administrateur de passer ce port dans le VLAN 10 (bureau) et je mets à jour le cahier de brassage. Vérification : ipconfig /renew → 192.168.10.x, accès au serveur et à l'imprimante. »

Perd des points : modifier l'IP du poste en fixe pour « forcer » le bon réseau (le port reste dans le mauvais VLAN, rien ne passe).

9. Pièges et variantes

Piège Deux postes dans deux VLAN différents ne communiquent pas même avec des adresses du même réseau IP : le VLAN sépare au niveau 2, il faut un routage inter-VLAN. Un hub (ancien) répète tout sur tous les ports : collisions, lenteur — à remplacer, ce n'est pas une « panne » à configurer.
